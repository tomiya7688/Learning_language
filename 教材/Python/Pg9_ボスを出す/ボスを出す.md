# Pg9. pygame「ボスを出す」

Pg8では、敵が順番に出てくるようになりました。

でも、通常敵が全部いなくなったあとに何も起きません。

> **「雑魚全部いなくなった。で、終わり？？？」**

今回は、通常敵の出現が全部終わり、画面上に通常敵がいなくなったらボスを出します。

複雑なAIはまだやりません。

まずは、

> **最後にHPの多い大きな敵が出る**

だけで、1本のゲームとして締まることを体験します。

---

## Pg9-1. 今回作るもの

[boss_battle.py](./boss_battle.py) を開いてください。

`boss` は「ボス」、`battle` は「戦い」という意味です。

今回は、

```text
通常敵が順番に出る
↓
出現予定を全部出し終える
↓
画面上から通常敵がいなくなる
↓
ボス出現
↓
ボスHPを0にする
↓
ゲームクリア
```

まで作ります。

---

## Pg9-2. 「全部出し終えた」を見る

```python
total_enemies = len(spawn_positions_x)
```

で、出現予定の敵の総数を持っています。

`spawn_index` は「何体目まで出したか」でした。

なので、

```python
spawn_index >= total_enemies
```

なら、

> **出す予定の通常敵は全部出し終えた**

と判断できます。

---

## Pg9-3. 倒し損ねても宇宙空間に取り残さない

ボス出現を「倒した数」で決めると、1体でも画面下へ逃した瞬間に条件を満たせなくなります。

> **「1体逃しただけでボス一生来ないん？？？」**

それは進行不能です。

だから今回は、

> **全部出し終えた + 画面上に通常敵がいない**

をボス出現条件にします。

---

## Pg9-4. ボス用の変数

ボス用の状態・位置・HPを用意します。

```python
boss_active = False
boss_x = 320
boss_y = 90
boss_hp = 20
```

`boss_active` の `active` は「有効・活動中」という意味です。

```text
False
→ まだボスは出ていない

True
→ ボスが出ている
```

として使います。ゲーム開始時はまだボスがいないので `False` です。

`boss_x` と `boss_y` はボスの中心位置です。

```text
boss_x = 320
→ 横320ピクセル

boss_y = 90
→ 上から90ピクセル
```

画面は640×480なので、`x = 320` は横方向の中央です。`y = 90` は画面上側なので、ボスは上の中央付近に出ます。

`boss_hp` はボスの残りHPです。

```python
boss_hp = 20
```

から始め、プレイヤーの弾が1発当たるたびに1減らします。

### ボスHPを変えてみる

`boss_battle.py` の **63行目** を変更します。

VS Codeで **Ctrl + F**、macOSでは **Command + F** を押して、

```text
boss_hp = 20
```

を検索してください。

変更前:

```python
boss_hp = 20
```

変更後:

```python
boss_hp = 10
```

保存して再実行し、ボスを倒すまでに必要な弾数が少なくなれば成功です。

確認したら `20` に戻しておいてください。この章の完成形ではHP20を使います。

---

## Pg9-5. 条件が揃ったらボス出現

```python
if (
    spawn_index >= total_enemies
    and not enemies
    and not boss_active
):
    boss_active = True
```

で、

- 出す予定の通常敵を全部出し終えた
- 今、画面上に通常敵が残っていない
- まだボスが出ていない

ならボスを出します。

---

## Pg9-6. ボスは大きく描く

ボスが出ている間だけ、四角形を画面へ描きます。

```python
if boss_active:
    pygame.draw.rect(
        screen,
        (180, 80, 255),
        (boss_x - 60, boss_y - 30, 120, 60)
    )
```

`pygame.draw.rect()` は四角形を**実際に画面へ描く**関数です。

渡しているものは、

```text
screen
→ どの画面へ描くか

(180, 80, 255)
→ 何色で描くか

(boss_x - 60, boss_y - 30, 120, 60)
→ 左端・上端・幅・高さ
```

です。

`(180, 80, 255)` はRGBです。

```text
赤 = 180
緑 = 80
青 = 255
```

青が最大で赤も強めなので、紫系の色になります。

ボスの大きさは、

```text
幅  = 120ピクセル
高さ = 60ピクセル
```

です。

この教材では `boss_x` と `boss_y` をボスの中心として使います。

幅120の半分は60、高さ60の半分は30なので、

```text
boss_x - 60
→ 左端

boss_y - 30
→ 上端
```

とすると、**幅120・高さ60の四角形の中心を `boss_x, boss_y` に合わせられます**。

通常敵は幅40・高さ30なので、ボスは見た目でも明らかに大きくなります。

---

## Pg9-7. ボスにもRectを作る

弾との重なりを調べるため、同じ位置と大きさのRectも用意します。

```python
boss_rect = pygame.Rect(
    boss_x - 60,
    boss_y - 30,
    120,
    60
)
```

`pygame.Rect()` は、

```text
左端のx
上端のy
幅
高さ
```

を持つ四角形を用意します。

ここでも描画と同じ、

```text
boss_x - 60
boss_y - 30
120
60
```

を使っています。

そのため、**画面に見えているボスと、当たり判定に使う四角形の位置・大きさが一致**します。

大事なのは、`pygame.Rect()` を作っただけでは画面には何も描かれないことです。

```text
pygame.Rect(...)
→ 位置と大きさを持つ四角を用意する

pygame.draw.rect(...)
→ 四角形を実際にscreenへ描く
```

という違いがあります。

---

## Pg9-8. 弾が当たったらHPを減らす

プレイヤー弾にも `bullet_rect` があるので、ボスのRectと重なったか調べます。

```python
if bullet_rect.colliderect(boss_rect):
    bullets_to_remove.append(bullet)
    boss_hp = boss_hp - 1
```

`bullet_rect.colliderect(boss_rect)` は、

```text
プレイヤー弾の四角形
と
ボスの四角形
```

が重なっているかを調べます。

重なっていれば `True` になり、`if` の中を実行します。

```python
bullets_to_remove.append(bullet)
```

で当たった弾をあとで消す対象へ入れ、

```python
boss_hp = boss_hp - 1
```

でボスHPを1減らします。

通常敵は1発で消えますが、ボスはHP20から1ずつ減るので、何発も当てる必要があります。

---

## Pg9-9. ボスHPを表示する

ボスがあと何発で倒せるか分かるように、残りHPを文字で表示します。

### `render()` で文字画像を作る

`boss_battle.py` の **248行目** では、

```python
boss_text = font.render(
    f"BOSS HP: {boss_hp}",
    True,
    (255, 255, 255)
)
```

として文字画像を作っています。

`font.render()` に渡しているものは、

```text
f"BOSS HP: {boss_hp}"
→ 表示する文章

True
→ 文字の縁を滑らかにする指定

(255, 255, 255)
→ 文字色
```

です。

`(255, 255, 255)` はRGBがすべて最大なので白です。

`render()` の結果は、画面に直接表示されるのではなく、**文字の画像**として `boss_text` に入ります。

### `blit()` で文字画像を描く

次の **255行目** に、

```python
screen.blit(boss_text, (220, 10))
```

があります。

`blit()` は、作った画像を `screen` に描く処理です。

`(220, 10)` は `boss_text` の左上位置なので、

```text
画面の左から220ピクセル
画面の上から10ピクセル
```

の場所へボスHPを描きます。

### 最後に画面へ反映する

さらに **265行目** の、

```python
pygame.display.flip()
```

で、このフレームで描いたボスやHP文字を実際の画面へ反映します。

つまり、

```text
render()
→ BOSS HPの文字画像を作る
↓
blit()
→ 文字画像をscreenへ描く
↓
display.flip()
→ 描いた内容を画面へ反映する
```

という順番です。

## Pg9-10. ボスを倒したらクリア

```python
if boss_active and boss_hp <= 0:
    game_clear = True
    running = False
```

とします。

今回は最低限なので、専用のクリア画面はまだ作りません。

まずは、

> **最後の強い敵を倒したら終わる**

というゲームの区切りを作ります。

---

## Pg9-11. ボスも「通常敵の延長」

今回のボスは、特別な魔法を使うわけでも複雑なAIを持つわけでもありません。

やっていることは、

```text
座標がある
↓
大きさがある
↓
Rectがある
↓
弾と当たる
↓
HPが減る
```

です。

つまり、

> **普通の敵を少し大きくして、HPを持たせたもの**

として考えられます。

---

## Pg9-12. これで1本のゲームになる

ここまでで、

```text
プレイヤーを動かす
↓
撃つ
↓
敵が出る
↓
敵も撃つ
↓
通常敵を倒すか、画面下へ抜ける
↓
全出現が終わって画面上に敵がいなくなる
↓
ボスが出る
↓
ボスを倒す
↓
クリア
```

までつながりました。

まだ見た目は図形だけですが、

> **ゲームの流れ自体はほぼ完成**

です。

## Pg9-14. ここまでで覚えること

1. `spawn_index` と `total_enemies` で通常敵を全部出し終えたか判断できる
2. 条件が揃ったらボスを出せる
3. `boss_active` で出現状態を管理できる
4. ボスは通常敵より大きく描けば見分けやすい

7. ボスHPが0になったらゲームクリアにできる
8. ボスも通常敵の延長として考えられる
