# 13. 例外処理

数字を入力する欄で、うっかり「ねこ」と入力したとします。数字へ変えられずに長いエラー表示で終わってしまうと、使う人には何を直せばいいのか分かりにくくなります。

> **「ちょっと入力を間違えただけ！何を入れ直せばいいか教えて！」**

この章のプログラムは、整数にできる入力なら2倍の答えを表示し、それ以外なら「数字を入力してください」と案内を表示して終了します。何を入力すればいいか、その場で分かるようにする例です。

やり直すときは、プログラムをもう一度実行して数字を入力してください。このサンプルには、同じ実行中に入力をやり直す機能はありません。

---

## 13-1. 今回作るもの

まず、利用者に数字を入力してもらいます。

```text
数字を入力してください: 10
```

なら、

```text
2倍すると 20 です
```

これが、プログラムの表示する内容です。

でも、

```text
数字を入力してください: ねこ
```

と入力された場合は、

```text
数字を入力してください
```

プログラムは、この案内を表示して終了します。

---

## 13-2. なぜ例外処理が必要なの？

4章では、次のようなコードを使いました。

```python
number = int(input("数字を入力してください: "))
```

利用者が `10` と入力すれば問題ありません。

でも、

```text
ねこ
```

と入力すると、Pythonは数値へ変換できず、エラーで止まります。

> **「プログラム終わったんだけど？？？ちょっとミスっただけじゃん！！！」**

となります。

実際のプログラムでは、

- 数字のはずなのに文字が入力された
- ファイルが存在しなかった
- 必要なデータが見つからなかった

など、想定外のことが起こります。

そこで使うのが **例外処理** です。

---

## 13-3. 入力を受け取って変換を試す

[safe_number_input.py](./safe_number_input.py) を開いてください。

`safe` は「安全な」、`number` は「数字」、`input` は「入力」という意味です。

まず、Pythonは入力された文字列を `text` に保存します。

そのあとPythonは整数へ変換できるか試し、成功した値を `number` に保存します。

```python
# 入力された文字を text に保存します。
text = input("数字を入力してください: ")

try:
    # textを整数へ変換できたら、その整数を number に保存します。
    number = int(text)
except ValueError:
    print("数字を入力してください")
else:
    print("2倍すると", number * 2, "です")
```

---

## 13-4. `try` とは

`try` は、

> まず、この処理を試してみる

という意味です。

```python
try:
    number = int(text)
```

ここでは `text` を整数へ変換し、成功した整数を `number` に保存しようとしています。

---

## 13-5. `except` とは

もし `try` の中で特定の例外が起きたら、Pythonは `except` 側を実行します。

```python
except ValueError:
    print("数字を入力してください")
```

`int("ねこ")` のように、数値へ変換できない文字を渡すと `ValueError` が発生します。

そのとき、

```text
数字を入力してください
```

これが、プログラムの表示する内容です。

---

## 13-6. 例外とは？

Pythonでは、実行中に起きる問題の一部を **例外** と呼びます。

たとえば、

```python
int("ねこ")
```

では `ValueError`、

```python
open("not_found.txt", "r")
```

では `FileNotFoundError`

が起こることがあります。

例外処理では、

> どんな問題が起きたか

に合わせて処理を分けられます。

---

## 13-7. エラーと例外は何が違うの？

Pythonでは、文法の誤りによる構文エラーと、文法が正しくても実行中に起きる例外を区別します。

ただし、例外処理で扱えるのは主に**実行中に発生する例外**です。

たとえば、書き方そのものを間違えた構文エラーは、基本的にはコードを直す必要があります。

```text
書き方が間違っている
→ コードを直す

入力やファイル状態によって起こる問題
→ 例外処理で対応できる場合がある
```

という違いです。

---

## 13-8. `else` は成功したとき

今回のサンプルでは、

```python
else:
    print("2倍すると", number * 2, "です")
```

も使っています。

`else` は、`try` の中で例外が起きなかったときに実行されます。

つまり、

```text
変換成功
→ else

変換失敗
→ except
```

です。

---

## 13-9. `finally` もある

数字の入力がうまくいったときも、入力ミスだったときも、最後に「終了します」と表示したいとします。それぞれに同じ表示を書くと、片方を書き忘れたり、変更し忘れたりします。

> **「結果はどちらでも、最後の案内は同じように出したい！」**

成功したときも失敗したときも最後に行う処理を、1か所に書くための書き方が `finally` です。

```python
try:
    print("処理中")
except ValueError:
    print("失敗")
finally:
    print("終了します")
```

`finally` の中の処理は、`try` の処理が成功しても例外が起きても実行されます。

---

## 13-10. ファイルが無い場合にも使える

メモを読むプログラムで、保存したメモのファイルを別のフォルダへ移してしまったとします。プログラムが探す場所にはファイルがないため、読み込みで止まります。

> **「メモを読めない理由が、ファイルの場所だと教えてほしい！」**

12章の次の読み込みでも、指定した場所にファイルがなければエラーになります。

```python
open("not_found.txt", "r", encoding="utf-8")
```

この例のファイル名は、見つからないファイルを表す練習用の名前です。

例外処理を使えば、

```python
try:
    with open("not_found.txt", "r", encoding="utf-8") as file:
        text = file.read()
except FileNotFoundError:
    print("ファイルが見つかりません")
```

この例は、ファイルが見つからないことを画面で知らせます。ファイル名や置いた場所を確認する手がかりになります。

---

## 13-11. 何でも `except:` にしない

次のような書き方もできます。

```python
try:
    number = int(text)
except:
    print("エラー")
```

ただし、この書き方では想定していない例外もまとめて扱ってしまいます。

なぜなら、

> 何が原因で失敗したのか分からなくなる

からです。

できるだけ、

```python
except ValueError:
```

や、

```python
except FileNotFoundError:
```

処理する例外は、次のように想定しているものを指定してください。

---

## 13-12. 例外を握り潰さない

さらに良くないのが、

```python
try:
    number = int(text)
except:
    pass
```

です。

これだと、何か問題が起きても何も表示されません。

利用者からすると、

> 「押したのに何も起きないんだけど？」

となります。

例外処理は、エラーを消すためではありません。

**問題が起きたときに、どうするか決めるための仕組み**です。

---

## 13-13. 自分で変えてみる

表示メッセージを変えてみてください。

```python
except ValueError:
    print("その文字は数字に変換できません")
```

また、入力した数字を3倍にしても構いません。

```python
print("3倍すると", number * 3, "です")
```

---

## 13-14. ここまでで覚えること

この章で扱った内容をまとめます。

1. 実行中に起きる問題の一部を例外と呼ぶ
2. `try` で問題が起きるかもしれない処理を試せる
3. `except` で特定の例外へ対応できる
4. `ValueError` は数値変換失敗などで起こる
5. `FileNotFoundError` はファイルが見つからないときに起こる
6. `else` は例外が起きなかったときに使える
7. `finally` は最後に必ず実行したい処理に使える
8. 何でも `except:` にせず、想定する例外を指定する
9. 例外処理は問題を隠すためではなく、問題が起きたときの動作を決めるために使う
