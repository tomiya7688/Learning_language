## ゲームの準備・実行・片付けをたどる

敵や弾が増えても、ゲームを起動して終了する順序は同じです。準備と片付けを画面を更新する処理へ混ぜると、ウィンドウを作る場所や閉じる場所を探しにくくなります。Pygameの準備・ゲームの実行・片付けは、起動ファイル `main.py` の `main`（開始する処理）という関数にまとめます。関数は、処理へ名前を付けた定義で、`main()` と書くとPythonが定義内の処理を実行します。

ゲームのウィンドウ、画面更新の間隔を測る道具、更新を続けるかどうかの情報と操作は、`game.py` の `Game`（ゲーム全体）というクラスにまとまっています。クラスは情報と操作をまとめる定義で、`Game()` と書くとPythonがゲーム1つ分の情報を作ります。

### 起動用の `main.py` 全体

VS Codeの左側のファイル一覧で、練習用フォルダ内の `src/main.py` を開いてください。VS Codeに `src/main.py` のコードが表示されます。Windows / LinuxはCtrl + A、macOSはCommand + Aを押して、`src/main.py` のコード全体を選択してください。`src/main.py` の選択した部分へ次の全体コードを貼り付けてください。Windows / LinuxはCtrl + S、macOSはCommand + Sを押して、コメントを含む全体コードを `src/main.py` へ保存してください。

このコードの元ファイル：[`main.py` の 1〜27行](./src/main.py#L1-L27)。

```python
# 起動と終了の順序を画面を更新する処理へ混ぜると、準備や片付けの場所を探しにくくなります。
# main（開始する処理）へPygameの準備・ゲームの実行・終了後の片付けをまとめます。
# Pythonがゲーム画面・キー入力・描画を扱う道具pygameを読み込みます。
import pygame
# Pythonが同じsrcフォルダのgame.pyから、画面と進行をまとめるGame（ゲーム全体）の定義を読み込みます。
from game import Game

# defは名前を付けた処理の定義。main()と書くと、Pythonがmainの字下げした処理を実行します。
def main():
    # pygame.init()がPygameの各機能を使う準備をします。ゲームのウィンドウはGame()で作ります。
    pygame.init()
    # Pythonは、このtry内のGame()とgame.run()が正常に終わった場合も、エラーで中断した場合もfinallyへ進みます。
    try:
        # PythonがGame()でゲーム画面と進行に必要な情報を作り、変数gameから使えるようにします。
        game = Game()
        # game.run()が操作の確認と画面更新を繰り返します。閉じる操作でrunが終わると、Pythonはfinallyへ進みます。
        game.run()
    finally:
        # pygame.quit()が使用中のPygameの機能を片付け、開いていたゲームのウィンドウを閉じます。
        # Game()やgame.run()のエラーはfinallyでは解決されず、片付けの後にPythonがエラーを表示します。
        pygame.quit()

# __name__はPythonが付ける名前。main.pyを直接実行したとき、Pythonは__name__を"__main__"にします。
# ==は等しいか調べる記号。main.pyを読み込んだだけの場合、Pythonは次のmain()を実行しません。
if __name__ == "__main__":
    # Pythonがmain()を実行し、Pygameの準備からゲームの実行・終了後の片付けまでを開始します。
    main()
```

### 画面を開くまでと、画面更新を始める時点

1. Pythonは、直接実行した `main.py` の名前 `__name__` を `"__main__"` にします。末尾の `if __name__ == "__main__":` は2つの名前が等しいか調べ、等しい場合に `main()` を実行します。別のPythonファイルが `main.py` を読み込んだ場合、名前は `"__main__"` にならないため、Pythonは末尾の `main()` を実行せず、ゲーム画面も開きません。[main.py 23〜27行](./src/main.py#L23-L27)
2. `main()` 内の `pygame.init()` がPygameの各機能を使う準備をします。`pygame.init()` だけではゲームのウィンドウは開きません。[main.py 8〜11行](./src/main.py#L8-L11)
3. Pythonは `game = Game()` でゲーム1つ分の情報を作り、変数 `game` から使えるようにします。`Game()` を作る際にPythonが実行する `Game.__init__` は、幅 `settings.WIDTH`・高さ `settings.HEIGHT` のウィンドウを開き、戦闘用の `Battle` を用意します。`Battle`（戦闘）は、自機1機・敵3機・空の弾一覧を持ちます。[main.py 12〜15行](./src/main.py#L12-L15)・[game.py 10〜30行](./src/game.py#L10-L30)・[battle.py 13〜32行](./src/battle.py#L13-L32)
4. `game.run()` は、`Game.run`（ゲームを動かす処理）を実行して、操作確認・状態更新・描画・表示の繰り返しを始めます。`Game.run` は `Battle.update()` へ自機・敵・弾の移動と命中の確認を依頼し、`Battle.draw(self.screen)` へ背景・自機・残った弾と敵を描くよう依頼します。`pygame.display.flip()` が描画済みの画面をウィンドウへ表示します。[main.py 16〜17行](./src/main.py#L16-L17)・[game.py 32〜52行](./src/game.py#L32-L52)・[battle.py 42〜53行](./src/battle.py#L42-L53)・[battle.py 78〜97行](./src/battle.py#L78-L97)

`Game.run` が `self.clock.tick(settings.FPS)` を実行すると、画面更新は1秒あたり最大 `settings.FPS` 回に抑えられます。`self.clock` は `Game.__init__` が `pygame.time.Clock()` で用意した更新の間隔を測る道具です。処理に時間がかかる場合、実際の更新回数は上限より少なくなります。[game.py 17〜19行](./src/game.py#L17-L19)・[game.py 51〜52行](./src/game.py#L51-L52)

`self` は、そのクラスから作った情報を持つもの自身を表します。`Game.run` の `self.screen` は今動かしているゲームの描画先、`self.battle` は今動かしているゲームの戦闘です。

### ウィンドウを閉じた後の片付け

読者がゲームのウィンドウの閉じるボタンを押した後、プログラムは次の順に終了へ進みます。

1. `Game.handle_events` は `pygame.event.get()` が取り出した操作の知らせを順番に確認します。操作の種類 `event.type` が終了を表す `pygame.QUIT` だった場合、`Game.handle_events` はゲームの更新を続ける情報 `self.running` を `False`（続けない）にし、操作を確認する `for` の繰り返しを `break` で終えます。[game.py 54〜63行](./src/game.py#L54-L63)
2. `Game.run` は `self.running` が `False` になったことを確認して、画面更新を繰り返す `while` を `break` で終えます。`Game.run` は終了を確認した回の位置更新・描画・表示を行わず、呼び出し元の `main()` へ戻ります。[game.py 32〜41行](./src/game.py#L32-L41)・[main.py 16〜17行](./src/main.py#L16-L17)
3. Pythonは `main()` の `try:` 内の `game.run()` が終わると、`finally:` 内の `pygame.quit()` を実行します。`pygame.quit()` は使用中のPygameの機能を片付け、開いていたゲームのウィンドウを閉じます。`pygame.quit()` 自体はPythonのプログラムを終了する処理ではありません。この `main.py` は `main()` の後に実行する処理がないため、`main()` が終わると終了します。[main.py 12〜27行](./src/main.py#L12-L27)

`Game()` や `game.run()` の実行中にエラーが起きた場合も、Pythonは `finally:` 内の `pygame.quit()` を実行します。`finally:` はエラーを解決する処理ではないため、`main.py` ではPygameを片付けた後にPythonがエラーを表示します。`import pygame`、`from game import Game`、`pygame.init()` は `try:` の外にあるため、読み込みや準備の段階のエラーを、この `finally:` で片付ける構成ではありません。[main.py 3〜21行](./src/main.py#L3-L21)

Pygameの準備と片付けの対象は[pygame-ce公式のinit/quitの説明](https://pyga.me/docs/ref/pygame.html#pygame.init)、正常終了・エラー後の片付けは[Python公式のfinallyの説明](https://docs.python.org/ja/3/tutorial/errors.html#defining-clean-up-actions)、直接実行時の名前は[Python公式の__main__の説明](https://docs.python.org/ja/3/library/__main__.html)でも確認できます。

## 敵が登場する時点で `Enemy` を作る

敵が3機いると、各敵の位置と、その敵を動かす・描く操作を対応させる必要があります。位置の数値だけを別の一覧に並べると、どの敵を動かして描いているか追いにくくなります。敵1機の位置・大きさ・移動量と、その敵の操作を `Enemy`（敵）というクラスへまとめます。クラスは情報と操作をまとめる定義で、`Enemy(160, 80)` と書くと、Pythonは中心を横160・縦80に置く敵1機分の情報を作ります。

`Enemy(160, 80)` は中心をx=160、y=80に置いた敵1機です。`enemies`（敵の一覧）には3機を入れています。各敵の `move()` はyを `ENEMY_SPEED = 1` の分だけ増やし、下へ動かします。敵の形は40×40ピクセルの四角形です。

敵の移動処理へ弾との当たり判定まで加えると、敵が動く理由と弾が消える理由が一緒になって追いにくくなります。この章では、弾と敵が重なったときの判定・削除を `collisions.py`（衝突の処理）の `hit_enemies`（敵への命中を扱う処理）にまとめます。`bullet.rect.colliderect(enemy.rect)` は弾と敵の長方形が重なっているかを返し、`hit_enemies` が命中した弾と敵を一覧から外します。ファイル全体と判定の順序は[弾と敵が重なったときの処理](#弾と敵が重なったときの処理)で確認してください。

## 設定値の場所と意味

「敵がゆっくりすぎる。敵の動く量だけ変えたい！」というとき、移動の処理から数値を探して直すのは手間です。`settings.py` のsettingsは「設定」の意味で、ゲームの大きさ・最初の位置・動く量に名前を付けてまとめるファイルです。

たとえば `ENEMY_SPEED = 1` の `=` は、右の数値1を、左の名前 `ENEMY_SPEED`（敵の移動量）へ設定する書き方です。`enemy.py` は `import settings` で設定ファイルを読み込み、`settings.ENEMY_SPEED` で敵の移動量を使います。敵の設定値を2へ変えて再起動すると、敵を動かす処理も2を使います。

画面の高さも、画面を作る `game.py` と画面外を調べる `enemy.py` が、`settings.HEIGHT`（画面の高さ）を使います。各ファイルへ480を別々に書かず、同じ設定名を使うので、高さを変えるときは設定ファイルの1か所を直せます。

# 同じ画面の高さを各ファイルへ別々に書くと、変更する場所を探して直す必要があります。
# HEIGHT（高さ）のように値へ名前を付けると、画面を作る処理と画面外の判定が同じ設定を使えます。
# =は右側の値を左側の名前へ設定する書き方です。WIDTH（幅）= 640は横幅の設定へ640を指定します。

# ゲーム画面の左上は横0・縦0。ゲーム画面では横の値は右へ、縦の値は下へ進むほど増えます。
# 画面更新1回は、game.pyのGame.run（ゲームの繰り返し）がBattleの更新・描画を呼び、画面へ表示する1巡です。
# 背景はBattle、自機はPlayer、弾はBullet、敵はEnemyが描き、Gameは描画済みの画面を表示します。

# WIDTH（幅）はゲーム画面の横幅。game.pyが幅640ピクセルの画面を作ります。
# player.pyもWIDTHを使い、幅40の自機の左端を0〜600へ収めて、画面外へ出ないようにします。
WIDTH = 640
# HEIGHT（高さ）はゲーム画面の縦幅。game.pyが高さ480ピクセルの画面を作ります。
# enemy.pyとbullet.pyもHEIGHTを読み、機体や弾が画面の下へ出たかを調べます。
# player.pyもHEIGHTを使い、高さ40の自機の上端を0〜440へ収めて、画面外へ出ないようにします。
HEIGHT = 480

# FPSはframes per second（1秒あたりの画面更新回数）の略。game.pyが更新回数の上限に使います。
# game.pyはclock.tick(settings.FPS)へ60を指定し、速すぎる更新を待たせます。FPS=60は毎秒60回の更新を保証しません。
# 敵は更新1回ごとに動くので、毎秒30回しか更新できない場合は毎秒60回の場合より遅く動きます。
FPS = 60

# PLAYER（プレイヤー）は操作する自機、Xは横の位置。PLAYER_Xは自機の最初の横の中心位置です。
# player.pyが自機の中心を、ゲーム画面の左端から右へ320ピクセルの場所へ置きます。

# 自機の幅・高さはplayer.pyの40ピクセルなので、中心(320, 400)に置くと左上は(300, 380)です。
PLAYER_Y = 400

# player.pyは押した矢印に応じて、自機の横または縦の位置へ5ピクセルを足す・引く処理をします。
# 画面端に触れていなければ、右と上を同時に押すと横へ5・縦へ-5進み、斜めの距離は約7.1ピクセルで1方向だけより速く動きます。
# 画面端ではplayer.pyが自機を画面内へ戻すため、自機の実際の移動量は5より小さくなる場合があります。
PLAYER_SPEED = 5

# BULLET（弾）は自機が撃つ弾。BULLET_SPEEDは更新1回で弾が縦に進む量の大きさです。
# player.pyは8へ負の符号を付けて-8とし、弾1発の情報を作るbullet.pyへ指定します。
# bullet.pyは弾の縦の位置へ-8を足すので、縦の値が8減り、弾は上へ8ピクセル進みます。
BULLET_SPEED = 8

# ENEMY（エネミー）は敵。この章では開始時に3機置く赤い四角形で、ボスや敵の弾はまだありません。
# ENEMY_SPEEDは敵が更新1回で下へ進む量（ピクセル）。enemy.pyが敵の縦の位置へ1を足します。
# ENEMY_SPEEDを2にして再起動すると、敵は同じ1回の更新で下へ2ピクセル進みます。
# 毎秒60回更新できる場合、敵は設定1なら毎秒約60、設定2なら毎秒約120ピクセル進みます。
ENEMY_SPEED = 1

### 設定名と、その値を使う処理

### 1回の移動量と、1秒間の動きを分ける

[`game.py` 33〜52行](./src/game.py#L33-L52)の `Game.run()` は、[`battle.py` 42〜53行](./src/battle.py#L42-L53)の `Battle.update()` で位置を進め、[`battle.py` 77〜97行](./src/battle.py#L77-L97)の `Battle.draw()` で描く処理を順に呼びます。`Battle` が自機・弾・敵の各ファイルへ移動・描画を依頼し、`Game.run()` が `pygame.display.flip()` で描いた画面を表示します。

`Game.run()` の最後の `self.clock.tick(settings.FPS)` は、`settings.py` の `FPS = 60` を使い、更新が速すぎる場合に待つ処理です。PCの処理が遅い場合に、足りない更新を増やして毎秒60回へそろえる処理ではありません。[pygame-ce公式：更新回数を制限する](https://pyga.me/docs/ref/time.html#pygame.time.Clock.tick)

`settings.py` の `ENEMY_SPEED = 1` は、敵が1回の更新で下へ1ピクセル進む指定です。`enemy.py` は敵の移動量1を使うので、毎秒60回更新できる場合は約60ピクセル/秒、毎秒30回の場合は約30ピクセル/秒になります。この章では経過した秒数に合わせて移動量を補う処理がないため、更新が遅いと、同じ1秒間に敵が進む距離も短くなります。

`settings.py` の `PLAYER_SPEED = 5` は、`player.py` が使う横・縦それぞれの移動量です。画面端に触れていない場所で右と上を同時に押すと、自機は横へ5・縦へ-5ピクセル進みます。移動前と移動後の位置を直線で結んだ距離は、右だけを押す場合は5ピクセル、右上へ斜めに動く場合は約7.1ピクセルです。同じ更新回数でも、斜めの移動は1方向だけの場合より約1.4倍速く見えます。この章では斜めの移動量を短くして、1方向の速さへそろえる処理はありません。

### 弾の負の符号と、敵の正の移動量

[`player.py` 42〜47行](./src/player.py#L42-L47)は、`settings.py` の `BULLET_SPEED = 8` を `-settings.BULLET_SPEED` で-8にし、自機が撃つ弾へ指定します。負の符号は、縦の位置を減らす方向の指定です。弾の縦の位置へ-8を足すと、ゲーム画面では弾が上へ8ピクセル進みます。

[`enemy.py` 24〜33行](./src/enemy.py#L24-L33)は、`settings.py` の `ENEMY_SPEED = 1` を敵の縦の位置へ足します。敵の縦の中心が80なら、1回の更新後は81です。正の1を足すので、ゲーム画面では下へ1ピクセル進みます。この章の敵は開始時に3機置く赤い四角形で、敵の弾・ボス・追加で敵を出す間隔の設定はまだありません。

## 敵1機のコードを保存する

`Enemy`（敵）は、1機の位置・大きさ・移動量と操作をまとめるクラスです。敵を作る処理と動かす処理を分けると、開始位置を変えたいときは`__init__`、動き方を変えたいときは`move`を探せます。画面外の確認を`is_off_screen`、描画を`draw`へ分け、移動と消える理由を別々に追えるようにします。

1. VS Codeの左側のファイル一覧で、練習用フォルダの `src/enemy.py` をクリックしてください。敵のコードが編集画面へ表示されます。
2. `src/enemy.py` の編集画面で、Windows / LinuxはCtrl + A、macOSはCommand + Aを押してください。敵のコード全体が選ばれます。
3. 次の `enemy.py` 全体をコピーして、Windows / LinuxはCtrl + V、macOSはCommand + Vで選択したコードへ貼り付けてください。敵の処理と説明コメントが置き換わります。
4. Windows / LinuxはCtrl + S、macOSはCommand + Sで `src/enemy.py` を保存してください。敵のコードと説明コメントがファイルに保存されます。起動するファイルは `src/main.py` です。

元ファイル：[enemy.py 全体](./src/enemy.py)。

```python
# 敵が3機いると、各敵の位置と、その敵を動かす・描く操作を対応させる必要があります。
# Enemy（敵）へ1機分の位置・大きさ・移動量と、その敵の操作をまとめます。
# ピクセルはゲーム画面の位置や大きさを数える単位です。画面の左上は横0・縦0で、縦の値は下へ増えます。
# pygameは、位置を長方形で管理し、ゲーム画面へ長方形を描く道具です。
import pygame
# 同じsrcフォルダのsettings.pyから、敵の移動量ENEMY_SPEEDと画面の高さHEIGHTを読み込みます。
import settings

# クラスは情報と操作をまとめる定義。Enemyは敵1機を作るための定義です。
class Enemy:
    # 敵を作る・動かす・画面外か調べる・描く処理を分けて、各操作を探しやすくします。
    # __init__はEnemy(...)で敵を作るときにPythonが実行する初期設定の処理です。
    # selfは今設定する敵1機。self.rectやself.speedのように、その敵の情報を保持します。
    # x（横）/y（縦）は敵の中心位置。画面左端から右へx、画面上端から下へyピクセルです。
    # battle.pyのBattle（戦闘）はEnemy(160, 80)、Enemy(320, 40)、Enemy(480, 100)で3機を作ります。
    def __init__(self, x, y):
        # rectはrectangle（長方形）の略。self.rectに敵の位置と幅・高さをまとめます。
        # pygame.Rectは左端・上端・幅・高さの順。幅40・高さ40で、まず左上を(0, 0)にします。
        # 長方形の情報を作るだけでは敵は描かれません。敵を描く操作は下のdrawです。
        self.rect = pygame.Rect(0, 0, 40, 40)
        # centerは長方形の中心。幅・高さを保ったまま、敵の中心を指定位置へ移します。
        # 中心が(160, 80)なら幅・高さの半分20を引き、敵の左上は(140, 60)になります。
        self.rect.center = (x, y)
        # speedは速さの指定。敵を作るときにENEMY_SPEEDをその敵のself.speedへ保持します。
        # 配布時のENEMY_SPEED=1なら、敵は更新1回で下へ1ピクセル進みます。
        # 起動中のゲームのウィンドウを閉じ、settings.pyを保存してからsrc/main.pyを再実行してください。敵は保存後の移動量で作り直されます。
        self.speed = settings.ENEMY_SPEED

    # move（動かす）は、Battle.update_enemiesが更新のたびに敵1機へ行う操作です。
    def move(self):
        # self.rect.yは敵の長方形の上端。+=は今の値に右側の値を足す書き方です。
        # 移動量1なら、上端60・中心80の敵は上端61・中心81へ進みます。横の位置は変えません。
        self.rect.y += self.speed

    # is_off_screen（画面外か）は、敵の上端が画面下端を越えたか調べる操作です。
    def is_off_screen(self):
        # topは敵の上端、HEIGHTは画面の高さ480。>は左の値が右の値より大きいか調べます。
        # returnは調べた結果を呼び出したBattleへ返す指定。481 > 480はTrue（当てはまる）です。
        # 高さ480・移動量1の設定では、上端480はFalse（当てはまらない）。敵は見えませんが一覧へ残り、次の更新で上端481になります。
        # Enemy.is_off_screenは敵を削除しません。self.rect.top > settings.HEIGHTがTrueなら、Battle.update_enemiesが判定対象の敵を一覧から外します。
        return self.rect.top > settings.HEIGHT

    # draw（描く）は、Battle.drawが一覧に残っている敵1機へ行う操作です。
    # screenはgame.pyが用意し、Battleから指定されたゲームの描画先です。
    def draw(self, screen):
        # pygame.draw.rectがself.rectの位置・大きさで、塗りつぶした赤い長方形をscreenへ描きます。
        # 色の組は赤・緑・青の強さを0〜255で指定します。(255, 100, 100)は赤を強くした色です。
        # 描いた画面を表示するのはgame.pyのpygame.display.flip()です。
        pygame.draw.rect(screen, (255, 100, 100), self.rect)
```

### 作成時の移動量で、敵を下へ動かす

### 画面外かを調べて、結果を返す

> **「画面の下へ抜けた敵まで、いつまでも動かす必要はある？」**

この章では、画面の下へ抜けた敵を戻したり再利用したりしません。[enemy.py 35〜41行](./src/enemy.py#L35-L41)は、その敵の上端がゲーム画面の高さ480を越えたか調べ、結果を `True`（当てはまる）または `False`（当てはまらない）で `Battle` へ返します。`Enemy.is_off_screen()` 自身は敵を削除しません。

元ファイル：[enemy.py 35〜41行](./src/enemy.py#L35-L41)。

```python
    # is_off_screen（画面外か）は、敵の上端が画面下端を越えたか調べる操作です。
    def is_off_screen(self):
        # topは敵の上端、HEIGHTは画面の高さ480。>は左の値が右の値より大きいか調べます。
        # returnは調べた結果を呼び出したBattleへ返す指定。481 > 480はTrue（当てはまる）です。
        # 高さ480・移動量1の設定では、上端480はFalse（当てはまらない）。敵は見えませんが一覧へ残り、次の更新で上端481になります。
        # Enemy.is_off_screenは敵を削除しません。self.rect.top > settings.HEIGHTがTrueなら、Battle.update_enemiesが判定対象の敵を一覧から外します。
        return self.rect.top > settings.HEIGHT
```

`>` は左の値が右の値より大きいかを調べる記号です。`return` は、その結果を呼び出した処理へ返す指定です。高さ480のゲーム画面で見える縦の位置は0〜479なので、敵の上端が480なら敵は既に見えません。ただし、この章の比較は `>` なので、上端480では一覧から外す条件に当てはまりません。

| 敵の上端 | `上端 > 480` の結果 | 敵の一覧と描画での扱い |
| --- | --- | --- |
| 479 | `False`：480より大きくない | 敵の下の部分は画面外だが、上端側の1行は画面内。敵は一覧に残る |
| 480 | `False`：480と等しい | 敵は画面には見えないが、敵の一覧に残る |
| 481 | `True`：480を越えている | `Battle.update_enemies` が敵を一覧から外し、以後の移動・描画の対象に含めない |

中心の縦80・上端60の敵が弾に当たらず、移動量1で下へ進む例では、更新420回で上端が `60 + 420 = 480` になります。更新421回で上端481になり、一覧から外れます。移動量2なら上端480になるのは更新210回で、更新211回では上端482になって一覧から外れます。敵の移動量や開始位置によって、一覧から外れるまでの回数も変わります。

### 判定結果を受けたBattleが、敵を一覧から外す

[battle.py 66〜75行](./src/battle.py#L66-L75)の `Battle.update_enemies` は、敵1機を動かしてから画面外か調べます。`Enemy.is_off_screen()` が返した結果が `True` なら、`Battle.update_enemies` は判定対象の敵を `self.enemies`（敵の一覧）から外します。`Enemy.is_off_screen()` が返した結果が `False` なら、`Battle.update_enemies` は判定対象の敵を一覧から外しません。

元ファイル：[battle.py 66〜75行](./src/battle.py#L66-L75)。

```python
    # update_enemies の処理を定義する
    def update_enemies(self):
        # self.enemies[:] から enemy を1つずつ取り出して繰り返す
        for enemy in self.enemies[:]:
            # enemy.move() を実行する
            enemy.move()
            # enemy.is_off_screen() が成り立つなら
            if enemy.is_off_screen():
                # self.enemies.remove(enemy) を実行する
                self.enemies.remove(enemy)
```

`self.enemies[:]` は敵の一覧のコピーです。敵1機分の情報まで新しく複製する指定ではありません。コピーにも同じ敵1機分の情報が入っているため、`enemy.move()`が変更する位置は、元の一覧から使う敵の位置にも反映されます。`for enemy in ...` はコピーの各敵を順に取り出す指定で、`self.enemies.remove(enemy)` は元の一覧からその敵を外します。コピーを読まず元の一覧を読みながら先頭の敵Aを削除すると、次の敵Bが先頭へ移り、繰り返しが次の位置へ進んだときに敵Bを飛ばすことがあります。コピーなら、元の一覧を変えても、確認する敵A・B・Cの順は保たれます。

敵を一覧から外すと、[battle.py 77〜90行](./src/battle.py#L77-L90)は残った敵だけを描きます。背景を塗り直す `screen.fill(...)` が前の絵を消すため、一覧から外した敵の絵は描き直されません。敵を一覧から外す操作と、前の絵を背景色で消す操作は別です。

### 残っている敵を、赤い長方形で描く

## 弾と敵が重なったときの処理

「敵に弾が当たったのに、弾も敵も通り抜けた！」というままでは、敵を倒すゲームになりません。`hit_enemies` は、重なった弾1発と敵1機を一覧から外す関数です。関数は、処理をひとまとめにして名前を付けたものです。関数を実行するには、`hit_enemies(self.bullets, self.enemies)` のように、関数名のあとへ括弧を付けて書きます。この書き方で関数を実行することを「呼び出す」と呼びます。`Battle`（戦闘画面を管理するもの）が `hit_enemies` を実行し、どの弾と敵を調べるかを一覧で指定します。

### `collisions.py` を保存する

1. VS Codeで、この章の練習用フォルダにある `src/collisions.py` を開いてください。VS Codeの編集欄に `src/collisions.py` の内容が表示されます。
2. VS Codeの編集欄にある `src/collisions.py` の内容すべてを、この章の[collisions.py全体](./src/collisions.py)のコードへ置き換えてください。編集欄の内容が、命中した弾と敵を一覧から外す `hit_enemies` の定義に変わります。
3. VS Codeで `src/collisions.py` を開いた状態で、Ctrl + S（macOSではCommand + S）を押してください。編集した内容が、練習用フォルダ内の `src/collisions.py` へ保存されます。

このコードの元ファイル：[collisions.py 全体](./src/collisions.py)。

```python
# hit_enemiesは「弾が敵に重なったのに通り抜けた！」を防ぐため、重なった弾と敵を一覧から外します。
# 敵の移動へ命中時の削除も混ぜると追いにくいため、命中時の処理をcollisions.pyへまとめます。
# collisionsは衝突、hit_enemiesは敵への命中を扱う名前です。
# bulletsは自機の弾の一覧、enemiesは敵の一覧で、Battleが管理する元の一覧を受け取ります。
def hit_enemies(bullets, enemies):
    # bullets[:]は弾の一覧だけをコピーします。bullets[:]の各要素は、元のbulletsと同じ弾を指します。
    # hit_enemiesがbulletsから弾を外しても、bullets[:]には調べる弾が残るため、次の弾を飛ばしません。
    # 外側のforはbullets[:]から弾を1発ずつ選び、その1発をbullet（弾）という名前で使います。
    for bullet in bullets[:]:
        # hit_enemiesは弾を1発選ぶたびに、その時点の敵の一覧enemiesをenemies[:]でコピーします。
        # enemies[:]の各要素はenemiesと同じ敵を指します。hit_enemiesが前の弾でenemiesから外した敵は、新しいenemies[:]へ入りません。
        # 内側のforはenemies[:]から敵を1機ずつ選び、その1機をenemy（敵）という名前で使います。
        for enemy in enemies[:]:
            # rectはrectangle（長方形）の略で、弾・敵の位置と大きさを表します。
            # colliderectは2つの長方形の重なりを調べる操作です。
            # 弾と敵の長方形が面積を持って重なるとcolliderectはTrue（成り立つ）を返します。
            # 弾と敵の長方形の辺が接するだけか、弾と敵の長方形が離れている場合、colliderectはFalse（成り立たない）を返します。
            # ifはbullet.rect.colliderect(enemy.rect)がTrueのときだけ、bullets.remove(bullet)とenemies.remove(enemy)を行います。
            if bullet.rect.colliderect(enemy.rect):
                # removeは指定した要素を一覧から外す操作です。
                # bullets.removeは当たった弾を、Battleが管理する元の弾一覧から外します。
                # 以後、Battleはbulletsから外したbulletを移動・描画しません。
                bullets.remove(bullet)
                # enemies.removeは当たった敵を、Battleが管理する元の敵一覧から外します。
                # 以後、Battleはenemiesから外したenemyを移動・描画しません。
                enemies.remove(enemy)
                # hit_enemiesが命中後も同じ弾で別の敵への命中を調べ続けると、重なった場合に同じ弾を2回removeしてエラーになります。
                # breakは内側のfor enemy in enemies[:]（選んだ弾に重なる敵を探す繰り返し）だけを終えます。
                # 外側のfor bullet in bullets[:]は続き、hit_enemiesは次の弾についてenemiesに残っている敵を調べます。
                break
```

### `Battle` が判定を実行する場所

`self.bullets` は `Battle` が管理する自機の弾の一覧、`self.enemies` は敵の一覧です。`hit_enemies(self.bullets, self.enemies)` の括弧の中で、この2つの一覧を指定します。`hit_enemies` の中の `bullets` と `enemies` は、それぞれこの元の一覧を指します。新しい弾や敵を作る指定ではありません。

このコードの元ファイル：[battle.py 42〜53行](./src/battle.py#L42-L53)。

### 長方形が重なると命中する

`bullet.rect` は弾の位置・大きさを表す長方形、`enemy.rect` は敵の位置・大きさを表す長方形です。`rect` はrectangle（長方形）の略です。弾は幅6・高さ20ピクセル（[player.py 44〜47行](./src/player.py#L44-L47)）、敵は幅40・高さ40ピクセル（[enemy.py 16〜23行](./src/enemy.py#L16-L23)）です。弾・敵は長方形で描かれるため、この章ではその長方形どうしで命中を調べます。描画する場所は[bullet.py 33〜35行](./src/bullet.py#L33-L35)と[enemy.py 43〜49行](./src/enemy.py#L43-L49)です。

`bullet.rect.colliderect(enemy.rect)` の `colliderect` は、2つの長方形の重なりを調べる操作です。`colliderect` は面積を持って重なる場合に `True`（成り立つ）、離れている場合や辺が接するだけの場合に `False`（成り立たない）を返します。`if` は、`colliderect` の結果が `True` のときだけ、下の削除を行います。`colliderect` 自体は、弾や敵を一覧から外しません。

このコードの元ファイル：[collisions.py 14〜30行](./src/collisions.py#L14-L30)。

```python

            # colliderectは2つの長方形の重なりを調べる操作です。
            # 弾と敵の長方形が面積を持って重なるとcolliderectはTrue（成り立つ）を返します。
            # 弾と敵の長方形の辺が接するだけか、弾と敵の長方形が離れている場合、colliderectはFalse（成り立たない）を返します。

                # 以後、Battleはbulletsから外したbulletを移動・描画しません。
                bullets.remove(bullet)
                # enemies.removeは当たった敵を、Battleが管理する元の敵一覧から外します。
                # 以後、Battleはenemiesから外したenemyを移動・描画しません。

                # breakは内側のfor enemy in enemies[:]（選んだ弾に重なる敵を探す繰り返し）だけを終えます。
                # 外側のfor bullet in bullets[:]は続き、hit_enemiesは次の弾についてenemiesに残っている敵を調べます。

```

| 判定する瞬間の弾の上端・下端 | 敵との位置関係 | `colliderect` の結果と `hit_enemies` の処理 |
| --- | --- | --- |
| 上端101・下端121 | 敵の下端100から離れている | `colliderect` は `False` を返し、`hit_enemies` はこの弾と敵を一覧へ残す |
| 上端100・下端120 | 弾の上端と敵の下端が100で接するだけ | `colliderect` は `False` を返し、`hit_enemies` はこの弾と敵を一覧へ残す |

### コピーするのは一覧で、弾や敵は同じもの

`bullets[:]` の `[:]` は弾の一覧をコピーする書き方です。`bullets[:]` の各要素は、元の `bullets` と同じ弾を指します。`enemies[:]` も敵の一覧だけをコピーし、各要素は同じ敵を指します。該当する2つの `for` は[collisions.py 6〜13行](./src/collisions.py#L6-L13)で確認してください。`for` は一覧から要素を順に1つずつ選び、下に字下げした処理を繰り返します。

弾の一覧が「弾A・弾B・弾C」のとき、元の一覧を直接読んで弾Aを外すと、弾Bが前へ詰まります。そのまま次の位置を読む繰り返しでは、弾Bを飛ばして弾Cへ進みます。`bullets[:]` のコピーには「弾A・弾B・弾C」の並びが残るため、`hit_enemies` は弾Aを元の一覧から外したあとも、弾B、弾Cの順に調べられます。

`enemies[:]` を作るのは、外側の繰り返しが弾を1発選ぶたびです。弾Aで敵Xを元の敵一覧から外した場合、弾Bのために作る敵一覧のコピーには敵Xが入りません。`hit_enemies` は倒した敵を次の弾で再び調べません。

### 命中した弾で、別の敵を探し続けない

`remove` は指定した要素を一覧から外す操作です。`bullets.remove(bullet)` は命中した弾を元の弾一覧から外し、`enemies.remove(enemy)` は命中した敵を元の敵一覧から外します。削除と `break` は[collisions.py 19〜30行](./src/collisions.py#L19-L30)で確認してください。

`hit_enemies` が命中後も同じ弾で敵を探し続けると、別の敵にも重なっていた場合、すでに一覧から外した弾をもう一度 `remove` しようとしてエラーになります。`break` は内側の「今選んでいる弾に重なる敵を探す」繰り返しだけを終えます。外側の「弾を1発ずつ選ぶ」繰り返しは続くため、`hit_enemies` は次の弾について残っている敵を調べます。

1発の弾が同時に複数の敵へ重なった場合、`hit_enemies` は敵一覧の順で最初に見つけた1機だけを外します。その後、`break` でその弾の敵探しを終えます。どの敵にも重ならない弾は、元の弾一覧へ残ります。

### 一覧から外した弾と敵が、画面から消えるまで

`hit_enemies` は元の弾一覧と敵一覧をその場で変更します。`Battle.update` は、戻り値で命中を受け取って削除するのではなく、`hit_enemies` に一覧の変更を任せています。`hit_enemies` に `return` はなく、Pythonは処理が終わると `None` という特別な値を呼び出す側へ返します。`Battle.update` は `None` を使いません。`Game.run` が `Battle.draw` を呼び出し、`Battle.draw` が変更済みの `self.bullets`（自機の弾の一覧）と `self.enemies`（敵の一覧）を描画に使います。

このコードの元ファイル：[battle.py 78〜97行](./src/battle.py#L78-L97)。

```python
    def draw(self, screen):
        # screen.fill((10, 10, 30)) を実行する
        screen.fill((10, 10, 30))

        # self.player.draw(screen) を実行する
        self.player.draw(screen)
        # self.draw_bullets(screen, self.bullets) を実行する
        self.draw_bullets(screen, self.bullets)

        # self.enemies から enemy を1つずつ取り出して繰り返す
        for enemy in self.enemies:
            # enemy.draw(screen) を実行する
            enemy.draw(screen)

    # draw_bullets の処理を定義する
    def draw_bullets(self, screen, bullets):
        # bullets から bullet を1つずつ取り出して繰り返す
        for bullet in bullets:
            # bullet.draw(screen) を実行する
            bullet.draw(screen)
```

`Battle.draw` は、まず背景を塗って前の絵を消し、元の弾一覧と敵一覧へ残っているものだけを描きます。命中して一覧から外れた弾と敵は、次の描画から対象に入りません。弾・敵を一覧から外す操作が、画面の絵を直接消すわけではありません。

このコードの元ファイル：[game.py 43〜50行](./src/game.py#L43-L50)。

```python

            self.battle.update()

            # self.battle.draw(self.screen) を実行する
            self.battle.draw(self.screen)

            # pygame.display.flip() を実行する
            pygame.display.flip()
```

`Game.run` は `Battle.update` で位置と一覧を更新し、`Battle.draw` に描画を依頼したあと、`pygame.display.flip()` で描画済みの画面を表示します。命中した弾と敵が画面から消えるのは、この順で一覧の変更が画面へ反映されるためです。

敵の移動量は、[`enemy.py` 24〜27行](./src/enemy.py#L24-L27)で敵を作るときに読み込まれます。`settings.py` を保存しただけでは、起動中の敵が持つ移動量は変わりません。次の操作でゲームを終了し、設定を変えて起動し直してください。

1. 起動中なら、ゲームのウィンドウの閉じるボタンを押してください。ゲームが終了し、実行したターミナルがコマンドを入力できる状態へ戻ります。
2. VS Codeの左側のファイル一覧で `src/settings.py` を開き、編集画面でWindows / LinuxはCtrl + F、macOSはCommand + Fを押してください。コード内の検索欄が表示されます。検索欄へ `ENEMY_SPEED = 1` と入力すると、敵の移動量の設定行が見つかります。
3. 検索した `ENEMY_SPEED = 1` の右側の1を2へ変えてください。[`settings.py` 44〜47行](./src/settings.py#L44-L47)の `# ENEMY_SPEEDは敵が更新1回で下へ進む量` から始まるコメントの「縦の位置へ1を足します」を「縦の位置へ2を足します」に変更してください。Windows / LinuxはCtrl + S、macOSはCommand + Sで `src/settings.py` を保存してください。次の起動で敵の移動量2が使われます。
4. VS Codeの **表示 → ターミナル** で、この章を実行したターミナルを表示してください。Windowsは `.\.venv\Scripts\python.exe src/main.py`、macOS / Linuxは `.venv/bin/python src/main.py` を入力してEnterキーを押してください。赤い3機の敵が初期位置から再び現れ、同じ更新回数なら変更前の2倍の距離を下へ進みます。弾を撃たず、敵が下へ移動する様子を比べてください。

| 比べる条件 | `ENEMY_SPEED = 1` | `ENEMY_SPEED = 2` |
| --- | --- | --- |
| 中心の縦位置80の敵を、1回更新する | 中心が81へ進む | 中心が82へ進む |
| 中心の縦位置80の敵を、60回更新する（弾が当たらない場合） | 中心が140へ進む | 中心が200へ進む |
| 毎秒60回更新できる場合の、1秒間の移動 | 下へ約60ピクセル | 下へ約120ピクセル |

5. 比べ終わったらゲームの閉じるボタンを押してください。ゲームが終了し、ターミナルが入力待ちへ戻ります。
6. VS Codeの `src/settings.py` で `ENEMY_SPEED = 2` の右側を1へ戻し、変更したコメントも「縦の位置へ1を足します」へ戻してください。Windows / LinuxはCtrl + S、macOSはCommand + Sで保存すると、配布時の敵の移動量1に戻ります。
7. VS Codeの **表示 → ターミナル** で同じターミナルを表示し、Windowsは `.\.venv\Scripts\python.exe src/main.py`、macOS / Linuxは `.venv/bin/python src/main.py` を入力してEnterキーを押してください。敵が更新1回につき下へ1ピクセル進む、最初の設定のゲームが起動します。次章へ進む前に、ゲームの閉じるボタンを押してください。ゲームが終了し、ターミナルが入力待ちへ戻ります。
