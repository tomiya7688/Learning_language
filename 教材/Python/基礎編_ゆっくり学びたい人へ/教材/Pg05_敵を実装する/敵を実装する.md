## ゲームの準備・実行・片付けをたどる

敵や弾が増えても、ゲームを起動して終了する順序は同じです。準備と片付けを画面を更新する処理へ混ぜると、ウィンドウを作る場所や閉じる場所を探しにくくなります。Pygameの準備・ゲームの実行・片付けは、起動ファイル `main.py` の `main`（開始する処理）という関数にまとめます。関数は、処理へ名前を付けた定義で、`main()` と書くとPythonが定義内の処理を実行します。

ゲームのウィンドウ、画面更新の間隔を測る道具、更新を続けるかどうかの情報と操作は、`game.py` の `Game`（ゲーム全体）というクラスにまとまっています。クラスは情報と操作をまとめる定義で、`Game()` と書くとPythonがゲーム1つ分の情報を作ります。

### 起動用の `main.py` 全体

VS Codeの左側のファイル一覧で、練習用フォルダ内の `src/main.py` を開いてください。VS Codeに `src/main.py` のコードが表示されます。Windows / LinuxはCtrl + A、macOSはCommand + Aを押して、`src/main.py` のコード全体を選択してください。`src/main.py` の選択した部分へ次の全体コードを貼り付けてください。Windows / LinuxはCtrl + S、macOSはCommand + Sを押して、コメントを含む全体コードを `src/main.py` へ保存してください。

このコードの元ファイル：[`main.py` の 1〜27行](./src/main.py#L1-L27)。

```python
# 起動と終了の順序を画面を更新する処理へ混ぜると、準備や片付けの場所を探しにくくなります。
# main（開始する処理）へPygameの準備・ゲームの実行・終了後の片付けをまとめます。
# Pythonがゲーム画面・キー入力・描画を扱う道具pygameを読み込みます。
import pygame
# Pythonが同じsrcフォルダのgame.pyから、画面と進行をまとめるGame（ゲーム全体）の定義を読み込みます。
from game import Game

# defは名前を付けた処理の定義。main()と書くと、Pythonがmainの字下げした処理を実行します。
def main():
    # pygame.init()がPygameの各機能を使う準備をします。ゲームのウィンドウはGame()で作ります。
    pygame.init()
    # Pythonは、このtry内のGame()とgame.run()が正常に終わった場合も、エラーで中断した場合もfinallyへ進みます。
    try:
        # PythonがGame()でゲーム画面と進行に必要な情報を作り、変数gameから使えるようにします。
        game = Game()
        # game.run()が操作の確認と画面更新を繰り返します。閉じる操作でrunが終わると、Pythonはfinallyへ進みます。
        game.run()
    finally:
        # pygame.quit()が使用中のPygameの機能を片付け、開いていたゲームのウィンドウを閉じます。
        # Game()やgame.run()のエラーはfinallyでは解決されず、片付けの後にPythonがエラーを表示します。
        pygame.quit()

# __name__はPythonが付ける名前。main.pyを直接実行したとき、Pythonは__name__を"__main__"にします。
# ==は等しいか調べる記号。main.pyを読み込んだだけの場合、Pythonは次のmain()を実行しません。
if __name__ == "__main__":
    # Pythonがmain()を実行し、Pygameの準備からゲームの実行・終了後の片付けまでを開始します。
    main()
```

### 画面を開くまでと、画面更新を始める時点

1. Pythonは、直接実行した `main.py` の名前 `__name__` を `"__main__"` にします。末尾の `if __name__ == "__main__":` は2つの名前が等しいか調べ、等しい場合に `main()` を実行します。別のPythonファイルが `main.py` を読み込んだ場合、名前は `"__main__"` にならないため、Pythonは末尾の `main()` を実行せず、ゲーム画面も開きません。[main.py 23〜27行](./src/main.py#L23-L27)
2. `main()` 内の `pygame.init()` がPygameの各機能を使う準備をします。`pygame.init()` だけではゲームのウィンドウは開きません。[main.py 8〜11行](./src/main.py#L8-L11)
3. Pythonは `game = Game()` でゲーム1つ分の情報を作り、変数 `game` から使えるようにします。`Game()` を作る際にPythonが実行する `Game.__init__` は、幅 `settings.WIDTH`・高さ `settings.HEIGHT` のウィンドウを開き、戦闘用の `Battle` を用意します。`Battle`（戦闘）は、自機1機・敵3機・空の弾一覧を持ちます。[main.py 12〜15行](./src/main.py#L12-L15)・[game.py 12〜34行](./src/game.py#L12-L34)・[battle.py 12〜32行](./src/battle.py#L12-L32)
4. `game.run()` は、`Game.run`（ゲームを動かす処理）を実行して、操作確認・状態更新・描画・表示の繰り返しを始めます。`Game.run` は、今のゲームが持つ戦闘 `self.battle` の `update()` へ自機・敵・弾の移動と命中の確認を依頼し、`self.battle.draw(self.screen)` へ背景・自機・残った弾と敵を描くよう依頼します。`pygame.display.flip()` が描画済みの画面をウィンドウへ表示します。[main.py 16〜17行](./src/main.py#L16-L17)・[game.py 36〜57行](./src/game.py#L36-L57)・[battle.py 43〜57行](./src/battle.py#L43-L57)・[battle.py 83〜104行](./src/battle.py#L83-L104)

`Game.run` が `self.clock.tick(settings.FPS)` を実行すると、画面更新は1秒あたり最大 `settings.FPS` 回に抑えられます。`self.clock` は `Game.__init__` が `pygame.time.Clock()` で用意した更新の間隔を測る道具です。処理に時間がかかる場合、実際の更新回数は上限より少なくなります。[game.py 21〜23行](./src/game.py#L21-L23)・[game.py 55〜57行](./src/game.py#L55-L57)

`Game` の定義内の `self` は、今操作しているゲーム自身を指す名前です。`Game.run` の `self.screen` は今動かしているゲームの描画先、`self.battle` は今動かしているゲームの戦闘です。

### ウィンドウを閉じた後の片付け

読者がゲームのウィンドウの閉じるボタンを押した後、プログラムは次の順に終了へ進みます。

1. `Game.handle_events` は `pygame.event.get()` が取り出した操作の知らせを順番に確認します。操作の種類 `event.type` が終了を表す `pygame.QUIT` だった場合、`Game.handle_events` はゲームの更新を続ける情報 `self.running` を `False`（続けない）にし、操作を確認する `for` の繰り返しを `break` で終えます。[game.py 59〜69行](./src/game.py#L59-L69)
2. `Game.run` は `self.running` が `False` になったことを確認して、画面更新を繰り返す `while` を `break` で終えます。`Game.run` は終了を確認した回の位置更新・描画・表示を行わず、呼び出し元の `main()` へ戻ります。[game.py 36〜45行](./src/game.py#L36-L45)・[main.py 16〜17行](./src/main.py#L16-L17)
3. Pythonは `main()` の `try:` 内の `game.run()` が終わると、`finally:` 内の `pygame.quit()` を実行します。`pygame.quit()` は使用中のPygameの機能を片付け、開いていたゲームのウィンドウを閉じます。`pygame.quit()` 自体はPythonのプログラムを終了する処理ではありません。この `main.py` は `main()` の後に実行する処理がないため、`main()` が終わると終了します。[main.py 12〜27行](./src/main.py#L12-L27)

`Game()` や `game.run()` の実行中にエラーが起きた場合も、Pythonは `finally:` 内の `pygame.quit()` を実行します。`finally:` はエラーを解決する処理ではないため、`main.py` ではPygameを片付けた後にPythonがエラーを表示します。`import pygame`、`from game import Game`、`pygame.init()` は `try:` の外にあるため、読み込みや準備の段階のエラーを、この `finally:` で片付ける構成ではありません。[main.py 3〜21行](./src/main.py#L3-L21)

Pygameの準備と片付けの対象は[pygame-ce公式のinit/quitの説明](https://pyga.me/docs/ref/pygame.html#pygame.init)、正常終了・エラー後の片付けは[Python公式のfinallyの説明](https://docs.python.org/ja/3/tutorial/errors.html#defining-clean-up-actions)、直接実行時の名前は[Python公式の__main__の説明](https://docs.python.org/ja/3/library/__main__.html)でも確認できます。

## 画面の進行を `Game` にまとめる

自機・敵・弾を動かす処理へ、ウィンドウの終了や画面の表示まで並べると、敵を直したいときもゲーム全体を探すことになります。ゲーム画面と更新を続ける情報は `Game`（ゲーム全体）へまとめ、自機・敵・弾の情報と操作は `Battle`（戦闘）へまとめます。`Game` は戦闘を `self.battle` として持つため、位置を更新する戦闘と、画面へ描く戦闘が同じだと分かります。

ウィンドウを作る処理は、画面を更新するたびに実行する必要がありません。`Game.__init__` は `main.py` が `Game()` を作る際に、ウィンドウ・更新間隔を測る道具・更新を続ける情報を1回用意します。戦闘用の自機・敵・弾を作る処理は `start_game`（ゲームを始める）へ分けるため、戦闘の作成を探す際にウィンドウの準備まで読み直す必要がありません。

操作ごとの分岐と、移動・描画・表示を同じ場所へ並べると、1回の画面更新の順序を追いにくくなります。`handle_events`（操作を確認する）は操作の知らせを調べる処理、`run`（動かす）は操作確認・戦闘の更新・描画・表示・待ち時間の順序を繰り返す処理へ分けます。`Game()` を作るだけでは `run` の繰り返しは始まらず、`main.py` の `game.run()` が繰り返しを始めます。[main.py 12〜17行](./src/main.py#L12-L17)

```python
# ゲームのウィンドウを閉じる処理と弾1発の移動を混ぜると、ゲーム全体が終わる場所を探しにくくなります。
# Game（ゲーム全体）へ画面と進行をまとめ、自機・敵・弾の管理はbattle.pyのBattle（戦闘）へ任せます。
# Pythonがウィンドウ・キー入力・描画・表示を扱う道具pygameを読み込みます。
import pygame
# Pythonが同じsrcのsettings.pyから、画面の幅WIDTH・高さHEIGHT・更新回数の上限FPSを読み込みます。
import settings
# Pythonが同じsrcのbattle.pyから、自機・敵・弾の情報と操作をまとめるBattle（戦闘）の定義を読み込みます。
from battle import Battle

# クラスは情報と操作をまとめた定義。Gameはゲーム画面と、画面更新を始めて終える操作をまとめます。
class Game:
    # __init__はGame()を作る際にPythonが実行する準備です。ウィンドウと、更新に使う情報を1回用意します。
    # selfは今作っているゲーム自身。self.screenのように、同じゲームへ情報を持たせます。
    def __init__(self):
        # pygame.display.set_modeが、幅settings.WIDTH・高さsettings.HEIGHTのウィンドウを作ります。
        # Gameはウィンドウに色や図形を描くための場所を、screen（画面）という名前のself.screenに保存します。
        self.screen = pygame.display.set_mode((settings.WIDTH, settings.HEIGHT))
        # pygame.display.set_captionが、ゲームのウィンドウのタイトルを「敵を実装する」にします。
        pygame.display.set_caption('敵を実装する')

        # pygame.time.Clock()が更新の間隔を測る道具を作り、Gameはclock（時計）という名前のself.clockへ保存します。
        # Game.runはself.clock.tick(settings.FPS)で、画面更新が速くなりすぎないように待ちます。
        self.clock = pygame.time.Clock()
        # Gameはrunning（動作中）という名前のself.runningをTrue（続ける）にし、runが画面更新を始められるようにします。
        self.running = True

        # Game.__init__がstart_game（ゲームを始める）を実行して、自機1機・敵3機・空の弾一覧を持つ戦闘を用意します。
        self.start_game()

    # ウィンドウの準備と戦闘の作成を分けると、start_game（ゲームを始める）から戦闘の作成場所を探せます。
    def start_game(self):
        # Battle（戦闘）が、自機や弾など、この章の戦闘で使う情報を作ります。
        # GameはBattle()で作った戦闘をself.battleへ保存し、後の更新と描画で同じ戦闘を使います。
        self.battle = Battle()

    # 1回の画面更新の順序をrun（動かす）へまとめると、操作確認から表示までの順を1か所で追えます。
    def run(self):
        # whileは条件が成り立つ間の繰り返し。Game.runはself.runningがTrueの間、画面更新を続けます。
        while self.running:
            # Game.runがhandle_events（操作を確認する）を実行し、届いたキーや閉じる操作の知らせを確認します。
            self.handle_events()
            # notはTrue/Falseを逆にする指定。self.runningがFalseならGame.runは次のbreakを実行します。
            if not self.running:
                # Game.runが画面更新のwhileを終えます。終了を確認した回の更新・描画・表示・待ち時間は省きます。
                break

            # Game.runが今の戦闘self.battleのupdate（状態を更新する）へ、自機・敵・弾の移動、画面外の弾と敵の削除、弾と敵の命中の確認を依頼します。
            self.battle.update()

            # Game.runが今の戦闘self.battleのdraw（描く）へ、描画先self.screenに背景・自機・残っている弾と敵を描くよう依頼します。
            self.battle.draw(self.screen)

            # pygame.display.flip()が、self.screenへ描画済みの背景・自機・残っている弾と敵をゲームのウィンドウへ表示します。
            pygame.display.flip()
            # Game.runがself.clock.tickで、更新回数の上限settings.FPSに合わせ、必要な時間だけ待ちます。
            # settings.pyのFPSはframes per second（毎秒の更新回数）。処理が遅い場合、実際の更新回数は上限より少なくなります。
            self.clock.tick(settings.FPS)

    # 操作ごとの分岐をhandle_events（操作を確認する）へ分けると、runから画面更新の順序を追えます。
    def handle_events(self):
        # Game.handle_eventsが、pygame.event.get()で取り出した操作の知らせの一覧をforで順番に確認します。
        # event（操作の知らせ）は、forが今回確認する1件の知らせを入れる名前です。
        for event in pygame.event.get():
            # Game.handle_eventsが知らせの種類event.typeを確認し、QUIT（終了）なら閉じる操作として扱います。
            if event.type == pygame.QUIT:
                # Game.handle_eventsがself.runningをFalse（続けない）にし、runが画面更新を終えるようにします。
                self.running = False
                # Game.handle_eventsが操作確認のforを終え、取り出した一覧の残りの知らせはBattleへ送りません。
                break

            # Game.handle_eventsが終了以外の知らせeventを今の戦闘self.battleへ渡し、Battleがキー入力を確認します。
            self.battle.handle_event(event)
```

`class Game:` は、ゲーム画面の情報と操作をまとめる定義です。`def run(self):` のようにクラス内で定義する関数を「メソッド」と呼びます。`Game` のメソッド内の `self` は、今操作しているゲーム自身を指します。`self.screen` や `self.battle` は、メソッドの間で同じゲームの画面や戦闘を使うための名前です。`Game.run` は定義を説明するときの名前で、今のゲームの処理を実行するコードは `main.py` の `game.run()` です。[main.py 12〜17行](./src/main.py#L12-L17)

### スペースキーを押した後の1回の更新

ゲームのウィンドウを選んでスペースキーを押した場合、`Game` と `Battle` は次の順序で弾を作り、画面へ表示します。シューティングゲームの発射にスペースキーを使う慣例に合わせ、`Battle.handle_event` はスペースキーの知らせを発射に使っています。

| 順序 | 実際の処理と結果 |
| --- | --- |
| 1. 押した知らせを調べる | `Game.run` が `self.handle_events()` を実行し、`Game.handle_events` が `pygame.event.get()` から操作の知らせを取り出す。終了の知らせでなければ、`Game.handle_events` は知らせ `event` を `self.battle.handle_event(event)` へ指定する。[game.py 40〜41行](./src/game.py#L40-L41)・[game.py 59〜72行](./src/game.py#L59-L72) |
| 2. 自機の位置から弾を作る | `Battle.handle_event` が、キーを押した知らせ `pygame.KEYDOWN` かつスペースキー `pygame.K_SPACE` であることを確認すると、`self.player.shoot()` で弾を作り、戦闘の弾一覧 `self.bullets` に追加する。`KEYUP`（キーを離した知らせ）では弾を作らない。[battle.py 34〜41行](./src/battle.py#L34-L41)・[player.py 44〜47行](./src/player.py#L44-L47) |
| 3. 自機・弾・敵の位置と命中を更新する | `Game.run` が `self.battle.update()` を実行する。`Battle.update` は押している矢印キーの状態 `pygame.key.get_pressed()` で自機を動かし、弾と敵を動かして画面外のものを一覧から外し、弾と敵が重なったかを確認する。[game.py 47〜48行](./src/game.py#L47-L48)・[battle.py 43〜81行](./src/battle.py#L43-L81) |
| 4. 更新後に残った物体を描く | `Game.run` が `self.battle.draw(self.screen)` を実行する。`Battle.draw` が背景を塗り、`Player.draw` へ自機、`Bullet.draw` へ残った弾、`Enemy.draw` へ残った敵を同じ描画先 `self.screen` に描くよう依頼する。[game.py 50〜51行](./src/game.py#L50-L51)・[battle.py 83〜104行](./src/battle.py#L83-L104)・[player.py 50〜55行](./src/player.py#L50-L55)・[bullet.py 33〜35行](./src/bullet.py#L33-L35)・[enemy.py 43〜49行](./src/enemy.py#L43-L49) |
| 5. 描いた画面を表示して更新の速さを抑える | `pygame.display.flip()` が描画済みの画面をウィンドウへ表示する。`Game.run` が `self.clock.tick(settings.FPS)` を実行し、設定した毎秒の更新回数の上限に合わせて必要な時間だけ待つ。[game.py 53〜57行](./src/game.py#L53-L57) |

`Battle.handle_event` が弾を作る時点は、同じ更新回の `Battle.update` が自機を動かすより前です。矢印キーとスペースキーを同じ更新回で使った場合、`Player.shoot` はその回の移動前の自機の位置から弾を作ります。`Battle.update` は、作ったばかりの弾も移動してから命中を調べます。[game.py 40〜48行](./src/game.py#L40-L48)・[battle.py 34〜57行](./src/battle.py#L34-L57)

`Game.run` の1回の更新で `Game.handle_events` が受け取る知らせは、1件とは限りません。`pygame.event.get()` は、その時点で蓄えられている知らせを一覧へ取り出し、蓄えた場所から取り除きます。`Game.handle_events` が閉じる知らせで `for` を終えると、取り出した一覧の残りを `Battle` へ送りません。確認しなかった知らせを次回へ戻す処理は、このコードにはありません。[game.py 59〜72行](./src/game.py#L59-L72)・[pygame-ce公式：操作の知らせを取り出す](https://pyga.me/docs/ref/event.html#pygame.event.get)

操作の知らせの一覧で、スペースキーの知らせが閉じる知らせより前なら、`Battle.handle_event` は終了の確認前に弾を作れます。ただし `Game.run` は閉じる知らせを確認した回の `self.battle.update()`・`self.battle.draw(self.screen)`・`pygame.display.flip()`・`self.clock.tick(settings.FPS)` を省くため、その回に作った弾を画面へ描いて表示しません。[game.py 40〜57行](./src/game.py#L40-L57)・[game.py 59〜72行](./src/game.py#L59-L72)

`self.clock.tick(settings.FPS)` は更新回数の上限を設定する処理で、毎秒60回の達成を保証しません。`settings.py` の配布時の `FPS = 60` より処理が遅ければ、実際の更新回数は少なくなります。`Game.run` は `tick` が返す経過時間を移動量に使っていないため、実際の更新回数が少ないと、自機・弾・敵が1秒間に動く距離も短くなります。[game.py 55〜57行](./src/game.py#L55-L57)・[settings.py 19〜22行](./src/settings.py#L19-L22)・[pygame-ce公式：更新回数の上限](https://pyga.me/docs/ref/time.html#pygame.time.Clock.tick)

描画先を指定する `self.battle.draw(self.screen)` と、描画済みの画面を表示する `pygame.display.flip()` は別の操作です。画面の表示については[pygame-ce公式：ウィンドウの表示を更新する](https://pyga.me/docs/ref/display.html#pygame.display.flip)でも確認できます。

## 自機・弾・敵を `Battle` で管理する

弾を撃ったのに、移動する一覧と描く一覧が別なら、撃った弾が画面へ出ません。敵を倒したのに、古い敵一覧を描けば敵が残って見えます。自機・弾・敵の情報と、その情報を使う操作は `Battle`（戦闘）へまとめ、同じ戦闘の情報を移動・命中・描画で使います。`Battle` は情報と操作をまとめるクラス、`Battle()` は戦闘1つ分の情報を作る書き方です。

`Game` はウィンドウの管理・操作の知らせの取り出し・画面の表示を担当します。`Battle` は、自機1機・自機の弾一覧・敵一覧を持ち、自機・弾・敵の各ファイルへ移動や描画を依頼します。[game.py 30〜72行](./src/game.py#L30-L72)・[battle.py 12〜104行](./src/battle.py#L12-L104)

戦闘の準備、入力、移動、描画を1か所へ書くと、弾を追加する場所や敵を外す場所を探しにくくなります。`Battle` の操作は、次の7つのメソッドへ分けます。メソッドはクラス内に定義した処理です。`self` は操作の対象になる戦闘1つ分の情報を指し、`self.bullets` はその戦闘が持つ自機の弾一覧です。

| 分ける処理 | 分ける理由と実行するタイミング |
| --- | --- |
| `__init__`：作成時の準備 | 自機や敵を移動のたびに作り直すと、位置が初期位置へ戻る。開始時の準備を毎回の更新から分け、Pythonが `Game.start_game` 内の `Battle()` を実行したときに自機と一覧を用意する。[game.py 30〜34行](./src/game.py#L30-L34)・[battle.py 15〜32行](./src/battle.py#L15-L32) |
| `handle_event`：操作の知らせへの対応 | スペースキーを押した知らせで弾を作る処理と、押している矢印キーの状態で自機を動かす処理はきっかけが違う。`Game.handle_events` が指定した知らせ1件を確認する処理へ発射を分ける。[game.py 59〜72行](./src/game.py#L59-L72)・[battle.py 34〜41行](./src/battle.py#L34-L41) |
| `update`：状態の更新 | 移動と命中の処理が各所に分かれると、移動の前と後のどちらで判定するか追いにくい。`Game.run` が呼び出す `Battle.update` へ、自機・弾・敵の移動から命中までの順をまとめる。[game.py 47〜48行](./src/game.py#L47-L48)・[battle.py 43〜57行](./src/battle.py#L43-L57) |
| `move_bullets`：弾一覧の更新 | 弾1発の移動と、弾一覧から画面外の弾を外す処理は役割が違う。`Battle.update` が指定した弾一覧を順に調べる処理へ分け、弾1発の移動は `Bullet.move` に任せる。[battle.py 49〜69行](./src/battle.py#L49-L69)・[bullet.py 22〜25行](./src/bullet.py#L22-L25) |
| `update_enemies`：敵一覧の更新 | 敵1機の移動と、敵一覧から画面外の敵を外す処理は役割が違う。`Battle.update` から一覧の更新を呼び出し、敵1機の移動は `Enemy.move` に任せる。[battle.py 52〜53行](./src/battle.py#L52-L53)・[battle.py 71〜81行](./src/battle.py#L71-L81)・[enemy.py 29〜32行](./src/enemy.py#L29-L32) |
| `draw`：戦闘の描画 | 位置や一覧を変更する処理と、絵を描く処理を混ぜると、どの位置・一覧を描くか追いにくい。`Game.run` から呼ばれる描画を `Battle.draw` へ分け、更新後の位置と一覧で背景・自機・弾・敵を描く。[game.py 50〜51行](./src/game.py#L50-L51)・[battle.py 83〜97行](./src/battle.py#L83-L97) |
| `draw_bullets`：弾一覧の描画 | 弾1発を描く処理と、弾一覧を順に描く処理は役割が違う。`Battle.draw` から一覧の描画を呼び出し、弾1発の位置・色・大きさは `Bullet.draw` に任せる。[battle.py 91〜104行](./src/battle.py#L91-L104)・[bullet.py 33〜35行](./src/bullet.py#L33-L35) |

元ファイル：[battle.py 全体（1〜104行）](./src/battle.py#L1-L104)。

```python
# Pythonが、キーの状態を調べたり画面へ色を塗ったりするpygameの機能を読み込みます。
import pygame
# Pythonが、同じsrcのsettings.pyから画面の大きさなどの設定を読み込みます。
import settings
# Pythonが、同じsrcのplayer.pyから自機の情報と操作をまとめるPlayer（プレイヤー）の定義を読み込みます。
from player import Player
# Pythonが、同じsrcのenemy.pyから敵1機の情報と操作をまとめるEnemy（敵）の定義を読み込みます。
from enemy import Enemy
# Pythonが、同じsrcのcollisions.pyから弾と敵の命中を調べて一覧を変更するhit_enemies（敵への命中）の定義を読み込みます。
from collisions import hit_enemies

# 自機・弾・敵の情報を別々に置くと、どの一覧を移動・命中・描画に使うか追いにくくなります。
# Battle（戦闘）へ自機と2つの一覧、その情報を使う操作をまとめます。ウィンドウの管理と表示はGameへ任せます。
class Battle:
    # 毎回の移動で自機や敵を作り直すと位置が戻るため、開始時にだけ用意する情報は__init__（作成時の準備）へ分けます。
    # selfは、今作っている戦闘1つ分の情報です。PythonがGame.start_game内のBattle()を実行すると、__init__が自機と一覧を用意します。
    def __init__(self):
        # playerはプレイヤー。Player()が自機1機の位置などを用意し、self.playerから同じ自機を後の移動・発射・描画で使います。
        self.player = Player()

        # bulletsは弾。self.bulletsはこの戦闘の自機が撃った弾の一覧で、[]はまだ弾がない空の一覧です。
        # Battle.handle_eventが弾を追加し、Battle.updateとBattle.drawが一覧に残っている弾を使います。
        self.bullets = []

        # enemiesは敵。self.enemiesはこの戦闘の敵の一覧で、最初に[]で空の一覧を作ります。
        self.enemies = []
        # Enemy(160, 80)が中心を画面左から160・上から80ピクセルに置く敵1機を作り、append（末尾へ追加）が敵一覧へ加えます。
        self.enemies.append(Enemy(160, 80))
        # Enemy(320, 40)が中心を画面左から320・上から40ピクセルに置く敵1機を作り、self.enemiesへ加えます。
        self.enemies.append(Enemy(320, 40))
        # Enemy(480, 100)が中心を画面左から480・上から100ピクセルに置く敵1機を作り、self.enemiesへ加えます。開始時の敵は合計3機です。
        self.enemies.append(Enemy(480, 100))

    # 押した知らせで弾を作る処理を、押している状態で移動する処理と混ぜないよう、handle_event（知らせへの対応）へ分けます。
    def handle_event(self, event):
        # eventは呼び出す側が指定した操作の知らせ1件、event.typeは知らせの種類、pygame.KEYDOWNはキーを押した知らせです。
        # andは左右の条件を両方満たす指定です。キーを押した知らせのときだけ、event.key（押したキー）がpygame.K_SPACE（スペースキー）か調べます。
        if event.type == pygame.KEYDOWN and event.key == pygame.K_SPACE:
            # self.player.shoot()が自機の位置から弾1発を作って返し、append（末尾へ追加）がその弾を自機の弾一覧self.bulletsへ加えます。
            # appendはself.bulletsに残っている以前の弾を置き換えません。弾の作成と一覧への追加だけでは、弾の移動や描画は行いません。
            self.bullets.append(self.player.shoot())

    # 移動と命中の処理が各所に分かれると、移動の前と後のどちらで判定するか追いにくいため、update（状態の更新）へ順序をまとめます。
    def update(self):
        # Game.runから依頼されたBattle.updateがget_pressed（押しているキーの状態）を調べ、Player.moveへ指定して自機を動かします。
        # スペースキーを押した知らせへの対応は、別のBattle.handle_eventが行います。
        self.player.move(pygame.key.get_pressed())

        # Battle.updateが自機の弾一覧self.bulletsをmove_bulletsへ指定し、弾の移動と画面外の弾の削除を依頼します。
        self.move_bullets(self.bullets)

        # Battle.updateがupdate_enemiesへ、敵の移動と画面外の敵の削除を依頼します。
        self.update_enemies()

        # hit_enemiesが、移動後に残った自機の弾と敵の重なりを調べ、命中した弾と敵を元のself.bullets/self.enemiesから外します。
        # Battle.updateは命中の戻り値を使わず、一覧の変更をhit_enemiesへ任せます。
        hit_enemies(self.bullets, self.enemies)

    # 弾1発の移動と、弾一覧からの削除は別の役割なので、一覧を順に管理する処理をmove_bullets（弾を動かす）へ分けます。
    def move_bullets(self, bullets):
        # bulletsは呼び出す側が指定した弾一覧です。bullets[:]は一覧だけのコピーで、各要素は元の一覧と同じ弾を指します。
        # forはコピーの弾を順に1発ずつbulletへ選びます。元のbulletsから削除しても、コピーの次の弾を飛ばしません。
        for bullet in bullets[:]:
            # bullet.move()が、選んだ弾bulletに保存した移動量で位置を1回進めます。
            bullet.move()
            # bullet.is_off_screen()（選んだ弾が画面外か）がTrue（成り立つ）を返した場合だけ、bullets.remove(bullet)を実行します。
            if bullet.is_off_screen():
                # bullets.remove(bullet)が選んだ弾bulletを元の弾一覧bulletsから外します。弾一覧の削除は画面の絵を直接消す操作ではありません。
                bullets.remove(bullet)

    # 敵1機を動かすEnemy.moveと、敵一覧を管理する処理を分けるため、update_enemies（敵の更新）へ繰り返しと削除をまとめます。
    def update_enemies(self):
        # self.enemies[:]は敵一覧だけのコピーで、各要素は同じ敵を指します。forがコピーからenemy（敵1機）を順に選びます。
        # 元のself.enemiesから敵を外しても、コピーの次の敵を飛ばしません。
        for enemy in self.enemies[:]:
            # 選んだ敵のEnemy.moveが、その敵に保存した移動量で位置を下へ1回進めます。
            enemy.move()
            # Enemy.is_off_screenがTrueを返すのは、移動後の敵の上端が画面の高さsettings.HEIGHTより下へ出た場合です。
            if enemy.is_off_screen():
                # Battle.update_enemiesが選んだ敵を元のself.enemiesから外し、以後の更新・描画の対象から外します。
                self.enemies.remove(enemy)

    # 一覧の変更と画面へ絵を描く処理を混ぜないよう、draw（描画）へ背景・自機・弾・敵を描く順序をまとめます。
    def draw(self, screen):
        # screenはGame.runが指定した描画先です。fill（塗る）が全体を暗い青に塗り、前に描いた絵を塗りつぶします。
        # (10, 10, 30)は赤・緑・青の強さの順で各値は0〜255です。fillは物体の位置や一覧を変更しません。
        screen.fill((10, 10, 30))

        # Battle.drawがPlayer.drawへ同じ描画先screenを指定し、現在の自機の位置に水色の三角形を描くよう依頼します。
        self.player.draw(screen)
        # Battle.drawがdraw_bulletsへ描画先screenと自機の弾一覧self.bulletsを指定し、残った弾の描画を依頼します。
        self.draw_bullets(screen, self.bullets)

        # forが、移動や命中の確認後に元の敵一覧self.enemiesへ残った敵を1機ずつenemyへ選びます。
        for enemy in self.enemies:
            # 選んだ敵のEnemy.drawが、同じ描画先screenへ現在の敵の位置に赤い長方形を描きます。
            enemy.draw(screen)

    # 弾1発を描くBullet.drawと、弾一覧を順に描く役割を分けるため、draw_bullets（弾の描画）へ繰り返しをまとめます。
    def draw_bullets(self, screen, bullets):
        # screenは呼び出す側が指定した描画先、bulletsは指定した弾一覧です。forが一覧に残った弾を1発ずつbulletへ選びます。
        for bullet in bullets:
            # bullet.draw(screen)が、選んだ弾bulletに保存した位置・大きさ・色で描画先screenへ弾を描きます。弾を移動したり一覧へ追加したりはしません。
            bullet.draw(screen)
```

### 弾を作ることと、弾を動かすことを分ける

`Battle.handle_event` の `event` は、呼び出す側の `Game.handle_events` が指定した操作の知らせ1件です。`event.type == pygame.KEYDOWN` は、その知らせがキーを押した知らせか調べます。`and` は左右の条件を両方満たす指定で、左側が成り立ったときだけ、Pythonは右側の `event.key == pygame.K_SPACE` で押したキーがスペースキーか調べます。キーを離した知らせ `KEYUP` や、マウスを動かした知らせでは、この発射処理を実行しません。[battle.py 34〜41行](./src/battle.py#L34-L41)

`self.bullets.append(self.player.shoot())` では、Pythonが先に `self.player.shoot()` を実行します。`Player.shoot` が自機の位置から弾1発を作って返し、`append`（末尾へ追加）が同じ弾を戦闘の弾一覧 `self.bullets` へ加えます。`append` は一覧に残っている以前の弾を置き換えません。作成と一覧への追加だけでは、弾の移動や描画は行いません。[battle.py 39〜41行](./src/battle.py#L39-L41)・[player.py 44〜47行](./src/player.py#L44-L47)

`Battle.update` は `pygame.key.get_pressed()` で今押しているキーの状態を調べ、その状態を `Player.move` へ指定します。`Player.move` は、押している矢印キーの方向へ自機を動かします。押した知らせ1件に対応する発射とは違い、自機の移動は押している間の更新ごとに行います。[battle.py 43〜47行](./src/battle.py#L43-L47)・[player.py 23〜41行](./src/player.py#L23-L41)・[pygame-ce公式のキーの状態](https://pyga.me/docs/ref/key.html#pygame.key.get_pressed)

### 一覧のコピーを読んで、元の一覧から外す

`Battle.update` の `self.move_bullets(self.bullets)` は、戦闘の自機の弾一覧を指定して弾の更新を呼び出します。`Battle.move_bullets` 内の `bullets` は同じ元の `self.bullets` を指します。引数は、呼び出す括弧の中で指定した情報です。`Battle.update` が使用する弾一覧を選び、`Battle.move_bullets` が指定された一覧の弾を移動・削除します。[battle.py 49〜69行](./src/battle.py#L49-L69)

`bullets[:]` は弾の一覧だけをコピーする書き方で、コピーの各要素は元の一覧と同じ弾を指します。`Battle.move_bullets` はコピーから選んだ `bullet` の `move()` で位置を進め、`bullet.is_off_screen()` が `True` を返した場合に、元の `bullets` からその弾を外します。弾の下端が画面の上端より上、または弾の上端が画面の高さより下へ出た場合が、この章の画面外です。弾の下端が0と同じ、または弾の上端が画面の高さ480と同じなら、その比較の条件は成り立ちません。[battle.py 59〜69行](./src/battle.py#L59-L69)・[bullet.py 22〜30行](./src/bullet.py#L22-L30)

元の弾一覧が「弾A・弾B・弾C」のとき、元の一覧を直接読む繰り返しで弾Aを外すと、弾Bが前へ詰まり、次に読む位置が弾Cになります。`Battle.move_bullets` は `bullets[:]` のコピーを読むので、弾Aを元の `bullets` から外した後も弾B・弾Cの順に処理できます。コピーの弾を動かすと、元の一覧からも使う同じ弾の位置が変わります。[battle.py 61〜69行](./src/battle.py#L61-L69)・[Python公式の一覧のコピー](https://docs.python.org/3/tutorial/datastructures.html#more-on-lists)

`Battle.update_enemies` も敵一覧 `self.enemies[:]` のコピーを読み、同じ敵1機を移動して、画面外なら元の `self.enemies` から外します。画面外の弾や敵を一覧から外すと、`hit_enemies` は外した物体を命中の判定に使わず、`Battle.draw` は外した物体を描きません。画面外で一覧から外れた敵も、弾が当たった敵も、敵一覧から外れるため、この章の敵3機がすべて弾で倒されたとは限りません。[battle.py 49〜81行](./src/battle.py#L49-L81)・[battle.py 83〜104行](./src/battle.py#L83-L104)

### 背景を塗り直して、残っている物体を描く

`Battle.draw` の `screen` は、`Game.run` が指定した描画先 `self.screen` です。`screen.fill((10, 10, 30))` が描画先全体を暗い青で塗りつぶし、前に描いた自機・弾・敵の絵を消します。赤・緑・青の強さをその順に0〜255で指定しており、青の値が30、赤と緑が10なので暗い青です。`fill` は自機・弾・敵の位置や一覧を変えません。[game.py 50〜51行](./src/game.py#L50-L51)・[battle.py 83〜87行](./src/battle.py#L83-L87)・[pygame-ce公式の塗りつぶし](https://pyga.me/docs/ref/surface.html#pygame.Surface.fill)

`Battle.draw` は同じ描画先 `screen` に、先に自機、次に残った自機の弾、最後に残った敵を描くよう各物体へ依頼します。絵が重なる場合は、後から描く敵の絵が弾や自機の絵の上に描かれます。描画用の `for` は元の弾一覧・敵一覧を読み、位置や一覧を変更しません。[battle.py 89〜104行](./src/battle.py#L89-L104)

`Battle.draw` が描くだけでは、ウィンドウの表示は更新されません。`Game.run` が `pygame.display.flip()` を実行すると、背景と残った物体を描き直した画面がウィンドウへ表示されます。弾や敵を一覧から外す操作、前の絵を背景色で塗りつぶす操作、描き直した画面を表示する操作は、それぞれ別の処理です。[game.py 47〜54行](./src/game.py#L47-L54)

## 敵が登場する時点で `Enemy` を作る

敵が3機いると、各敵の位置と、その敵を動かす・描く操作を対応させる必要があります。位置の数値だけを別の一覧に並べると、どの敵を動かして描いているか追いにくくなります。敵1機の位置・大きさ・移動量と、その敵の操作を `Enemy`（敵）というクラスへまとめます。クラスは情報と操作をまとめる定義で、`Enemy(160, 80)` と書くと、Pythonは中心を横160・縦80に置く敵1機分の情報を作ります。

`Enemy(160, 80)` は中心をx=160、y=80に置いた敵1機です。`enemies`（敵の一覧）には3機を入れています。各敵の `move()` はyを `ENEMY_SPEED = 1` の分だけ増やし、下へ動かします。敵の形は40×40ピクセルの四角形です。

敵の移動処理へ弾との当たり判定まで加えると、敵が動く理由と弾が消える理由が一緒になって追いにくくなります。この章では、弾と敵が重なったときの判定・削除を `collisions.py`（衝突の処理）の `hit_enemies`（敵への命中を扱う処理）にまとめます。`bullet.rect.colliderect(enemy.rect)` は弾と敵の長方形が重なっているかを返し、`hit_enemies` が命中した弾と敵を一覧から外します。ファイル全体と判定の順序は[弾と敵が重なったときの処理](#弾と敵が重なったときの処理)で確認してください。

## 設定値の場所と意味

「敵がゆっくりすぎる。敵の動く量だけ変えたい！」というとき、移動の処理から数値を探して直すのは手間です。`settings.py` のsettingsは「設定」の意味で、ゲームの大きさ・最初の位置・動く量に名前を付けてまとめるファイルです。

たとえば `ENEMY_SPEED = 1` の `=` は、右の数値1を、左の名前 `ENEMY_SPEED`（敵の移動量）へ設定する書き方です。`enemy.py` は `import settings` で設定ファイルを読み込み、`settings.ENEMY_SPEED` で敵の移動量を使います。敵の設定値を2へ変えて再起動すると、敵を動かす処理も2を使います。

画面の高さも、画面を作る `game.py` と画面外を調べる `enemy.py` が、`settings.HEIGHT`（画面の高さ）を使います。各ファイルへ480を別々に書かず、同じ設定名を使うので、高さを変えるときは設定ファイルの1か所を直せます。

### 1回の移動量と、1秒間の動きを分ける

[`game.py` 37〜57行](./src/game.py#L37-L57)の `Game.run()` は、[`battle.py` 43〜57行](./src/battle.py#L43-L57)の `Battle.update()` で位置を進め、[`battle.py` 83〜104行](./src/battle.py#L83-L104)の `Battle.draw()` で描く処理を順に呼びます。`Battle` が自機・弾・敵の各ファイルへ移動・描画を依頼し、`Game.run()` が `pygame.display.flip()` で描いた画面を表示します。

`Game.run()` の最後の `self.clock.tick(settings.FPS)` は、`settings.py` の `FPS = 60` を使い、更新が速すぎる場合に待つ処理です。PCの処理が遅い場合に、足りない更新を増やして毎秒60回へそろえる処理ではありません。[pygame-ce公式：更新回数を制限する](https://pyga.me/docs/ref/time.html#pygame.time.Clock.tick)

`settings.py` の `ENEMY_SPEED = 1` は、敵が1回の更新で下へ1ピクセル進む指定です。`enemy.py` は敵の移動量1を使うので、毎秒60回更新できる場合は約60ピクセル/秒、毎秒30回の場合は約30ピクセル/秒になります。この章では経過した秒数に合わせて移動量を補う処理がないため、更新が遅いと、同じ1秒間に敵が進む距離も短くなります。

`settings.py` の `PLAYER_SPEED = 5` は、`player.py` が使う横・縦それぞれの移動量です。画面端に触れていない場所で右と上を同時に押すと、自機は横へ5・縦へ-5ピクセル進みます。移動前と移動後の位置を直線で結んだ距離は、右だけを押す場合は5ピクセル、右上へ斜めに動く場合は約7.1ピクセルです。同じ更新回数でも、斜めの移動は1方向だけの場合より約1.4倍速く見えます。この章では斜めの移動量を短くして、1方向の速さへそろえる処理はありません。

### 弾の負の符号と、敵の正の移動量

```python
# Enemy（敵）へ1機分の位置・大きさ・移動量と、その敵の操作をまとめます。
# ピクセルはゲーム画面の位置や大きさを数える単位です。画面の左上は横0・縦0で、縦の値は下へ増えます。
# pygameは、位置を長方形で管理し、ゲーム画面へ長方形を描く道具です。
import pygame
# 同じsrcフォルダのsettings.pyから、敵の移動量ENEMY_SPEEDと画面の高さHEIGHTを読み込みます。
import settings

# クラスは情報と操作をまとめる定義。Enemyは敵1機を作るための定義です。
class Enemy:
    # 敵を作る・動かす・画面外か調べる・描く処理を分けて、各操作を探しやすくします。
    # __init__はEnemy(...)で敵を作るときにPythonが実行する初期設定の処理です。
    # selfは今設定する敵1機。self.rectやself.speedのように、その敵の情報を保持します。
    # x（横）/y（縦）は敵の中心位置。画面左端から右へx、画面上端から下へyピクセルです。
    # battle.pyのBattle（戦闘）はEnemy(160, 80)、Enemy(320, 40)、Enemy(480, 100)で3機を作ります。
    def __init__(self, x, y):
        # rectはrectangle（長方形）の略。self.rectに敵の位置と幅・高さをまとめます。
        # pygame.Rectは左端・上端・幅・高さの順。幅40・高さ40で、まず左上を(0, 0)にします。
        # 長方形の情報を作るだけでは敵は描かれません。敵を描く操作は下のdrawです。
        self.rect = pygame.Rect(0, 0, 40, 40)
        # centerは長方形の中心。幅・高さを保ったまま、敵の中心を指定位置へ移します。
        # 中心が(160, 80)なら幅・高さの半分20を引き、敵の左上は(140, 60)になります。
        self.rect.center = (x, y)
        # speedは速さの指定。敵を作るときにENEMY_SPEEDをその敵のself.speedへ保持します。
        # 配布時のENEMY_SPEED=1なら、敵は更新1回で下へ1ピクセル進みます。
        # 起動中のゲームのウィンドウを閉じ、settings.pyを保存してからsrc/main.pyを再実行してください。敵は保存後の移動量で作り直されます。
        self.speed = settings.ENEMY_SPEED

    # move（動かす）は、Battle.update_enemiesが更新のたびに敵1機へ行う操作です。
    def move(self):
        # self.rect.yは敵の長方形の上端。+=は今の値に右側の値を足す書き方です。
        # 移動量1なら、上端60・中心80の敵は上端61・中心81へ進みます。横の位置は変えません。
        self.rect.y += self.speed

    # is_off_screen（画面外か）は、敵の上端が画面下端を越えたか調べる操作です。
    def is_off_screen(self):
        # topは敵の上端、HEIGHTは画面の高さ480。>は左の値が右の値より大きいか調べます。
        # returnは調べた結果を呼び出したBattleへ返す指定。481 > 480はTrue（当てはまる）です。
        # 高さ480・移動量1の設定では、上端480はFalse（当てはまらない）。敵は見えませんが一覧へ残り、次の更新で上端481になります。
        # Enemy.is_off_screenは敵を削除しません。self.rect.top > settings.HEIGHTがTrueなら、Battle.update_enemiesが判定対象の敵を一覧から外します。
        return self.rect.top > settings.HEIGHT

    # draw（描く）は、Battle.drawが一覧に残っている敵1機へ行う操作です。
    # screenはgame.pyが用意し、Battleから指定されたゲームの描画先です。
    def draw(self, screen):
        # pygame.draw.rectがself.rectの位置・大きさで、塗りつぶした赤い長方形をscreenへ描きます。
        # 色の組は赤・緑・青の強さを0〜255で指定します。(255, 100, 100)は赤を強くした色です。
        # 描いた画面を表示するのはgame.pyのpygame.display.flip()です。
        pygame.draw.rect(screen, (255, 100, 100), self.rect)
```

### 画面外かを調べて、結果を返す

> **「画面の下へ抜けた敵まで、いつまでも動かす必要はある？」**

この章では、画面の下へ抜けた敵を戻したり再利用したりしません。[enemy.py 35〜41行](./src/enemy.py#L35-L41)は、その敵の上端がゲーム画面の高さ480を越えたか調べ、結果を `True`（当てはまる）または `False`（当てはまらない）で `Battle` へ返します。`Enemy.is_off_screen()` 自身は敵を削除しません。

元ファイル：[enemy.py 35〜41行](./src/enemy.py#L35-L41)。

```python
    # is_off_screen（画面外か）は、敵の上端が画面下端を越えたか調べる操作です。
    def is_off_screen(self):
        # topは敵の上端、HEIGHTは画面の高さ480。>は左の値が右の値より大きいか調べます。
        # returnは調べた結果を呼び出したBattleへ返す指定。481 > 480はTrue（当てはまる）です。
        # 高さ480・移動量1の設定では、上端480はFalse（当てはまらない）。敵は見えませんが一覧へ残り、次の更新で上端481になります。
        # Enemy.is_off_screenは敵を削除しません。self.rect.top > settings.HEIGHTがTrueなら、Battle.update_enemiesが判定対象の敵を一覧から外します。
        return self.rect.top > settings.HEIGHT
```

`>` は左の値が右の値より大きいかを調べる記号です。`return` は、その結果を呼び出した処理へ返す指定です。高さ480のゲーム画面で見える縦の位置は0〜479なので、敵の上端が480なら敵は既に見えません。ただし、この章の比較は `>` なので、上端480では一覧から外す条件に当てはまりません。

| 敵の上端 | `上端 > 480` の結果 | 敵の一覧と描画での扱い |
| --- | --- | --- |
| 479 | `False`：480より大きくない | 敵の下の部分は画面外だが、上端側の1行は画面内。敵は一覧に残る |
| 480 | `False`：480と等しい | 敵は画面には見えないが、敵の一覧に残る |
| 481 | `True`：480を越えている | `Battle.update_enemies` が敵を一覧から外し、以後の移動・描画の対象に含めない |

中心の縦80・上端60の敵が弾に当たらず、移動量1で下へ進む例では、更新420回で上端が `60 + 420 = 480` になります。更新421回で上端481になり、一覧から外れます。移動量2なら上端480になるのは更新210回で、更新211回では上端482になって一覧から外れます。敵の移動量や開始位置によって、一覧から外れるまでの回数も変わります。

### 判定結果を受けたBattleが、敵を一覧から外す

[battle.py 71〜81行](./src/battle.py#L71-L81)の `Battle.update_enemies` は、敵1機を動かしてから画面外か調べます。`Enemy.is_off_screen()` が返した結果が `True` なら、`Battle.update_enemies` は判定対象の敵を `self.enemies`（敵の一覧）から外します。`Enemy.is_off_screen()` が返した結果が `False` なら、`Battle.update_enemies` は判定対象の敵を一覧から外しません。

元ファイル：[battle.py 71〜81行](./src/battle.py#L71-L81)。

```python
    # 敵1機を動かすEnemy.moveと、敵一覧を管理する処理を分けるため、update_enemies（敵の更新）へ繰り返しと削除をまとめます。
    def update_enemies(self):
        # self.enemies[:]は敵一覧だけのコピーで、各要素は同じ敵を指します。forがコピーからenemy（敵1機）を順に選びます。
        # 元のself.enemiesから敵を外しても、コピーの次の敵を飛ばしません。
        for enemy in self.enemies[:]:
            # 選んだ敵のEnemy.moveが、その敵に保存した移動量で位置を下へ1回進めます。
            enemy.move()
            # Enemy.is_off_screenがTrueを返すのは、移動後の敵の上端が画面の高さsettings.HEIGHTより下へ出た場合です。
            if enemy.is_off_screen():
                # Battle.update_enemiesが選んだ敵を元のself.enemiesから外し、以後の更新・描画の対象から外します。
                self.enemies.remove(enemy)
```

`self.enemies[:]` は敵の一覧のコピーです。敵1機分の情報まで新しく複製する指定ではありません。コピーにも同じ敵1機分の情報が入っているため、`enemy.move()`が変更する位置は、元の一覧から使う敵の位置にも反映されます。`for enemy in ...` はコピーの各敵を順に取り出す指定で、`self.enemies.remove(enemy)` は元の一覧からその敵を外します。コピーを読まず元の一覧を読みながら先頭の敵Aを削除すると、次の敵Bが先頭へ移り、繰り返しが次の位置へ進んだときに敵Bを飛ばすことがあります。コピーなら、元の一覧を変えても、確認する敵A・B・Cの順は保たれます。

敵を一覧から外すと、[battle.py 83〜97行](./src/battle.py#L83-L97)は残った敵だけを描きます。背景を塗り直す `screen.fill(...)` が前の絵を消すため、一覧から外した敵の絵は描き直されません。敵を一覧から外す操作と、前の絵を背景色で消す操作は別です。

## 弾と敵が重なったときの処理

「敵に弾が当たったのに、弾も敵も通り抜けた！」というままでは、敵を倒すゲームになりません。`hit_enemies` は、重なった弾1発と敵1機を一覧から外す関数です。関数は、処理をひとまとめにして名前を付けたものです。関数を実行するには、`hit_enemies(self.bullets, self.enemies)` のように、関数名のあとへ括弧を付けて書きます。この書き方で関数を実行することを「呼び出す」と呼びます。`Battle`（戦闘画面を管理するもの）が `hit_enemies` を実行し、どの弾と敵を調べるかを一覧で指定します。

### `collisions.py` を保存する

1. VS Codeで、この章の練習用フォルダにある `src/collisions.py` を開いてください。VS Codeの編集欄に `src/collisions.py` の内容が表示されます。
2. VS Codeの編集欄にある `src/collisions.py` の内容すべてを、この章の[collisions.py全体](./src/collisions.py)のコードへ置き換えてください。編集欄の内容が、命中した弾と敵を一覧から外す `hit_enemies` の定義に変わります。
3. VS Codeで `src/collisions.py` を開いた状態で、Ctrl + S（macOSではCommand + S）を押してください。編集した内容が、練習用フォルダ内の `src/collisions.py` へ保存されます。

このコードの元ファイル：[collisions.py 全体](./src/collisions.py)。

```python
# hit_enemiesは「弾が敵に重なったのに通り抜けた！」を防ぐため、重なった弾と敵を一覧から外します。
# 敵の移動へ命中時の削除も混ぜると追いにくいため、命中時の処理をcollisions.pyへまとめます。
# collisionsは衝突、hit_enemiesは敵への命中を扱う名前です。
# bulletsは自機の弾の一覧、enemiesは敵の一覧で、Battleが管理する元の一覧を受け取ります。
def hit_enemies(bullets, enemies):
    # bullets[:]は弾の一覧だけをコピーします。bullets[:]の各要素は、元のbulletsと同じ弾を指します。
    # hit_enemiesがbulletsから弾を外しても、bullets[:]には調べる弾が残るため、次の弾を飛ばしません。
    # 外側のforはbullets[:]から弾を1発ずつ選び、その1発をbullet（弾）という名前で使います。
    for bullet in bullets[:]:
        # hit_enemiesは弾を1発選ぶたびに、その時点の敵の一覧enemiesをenemies[:]でコピーします。
        # enemies[:]の各要素はenemiesと同じ敵を指します。hit_enemiesが前の弾でenemiesから外した敵は、新しいenemies[:]へ入りません。
        # 内側のforはenemies[:]から敵を1機ずつ選び、その1機をenemy（敵）という名前で使います。
        for enemy in enemies[:]:
            # rectはrectangle（長方形）の略で、弾・敵の位置と大きさを表します。
            # colliderectは2つの長方形の重なりを調べる操作です。
            # 弾と敵の長方形が面積を持って重なるとcolliderectはTrue（成り立つ）を返します。
            # 弾と敵の長方形の辺が接するだけか、弾と敵の長方形が離れている場合、colliderectはFalse（成り立たない）を返します。
            # ifはbullet.rect.colliderect(enemy.rect)がTrueのときだけ、bullets.remove(bullet)とenemies.remove(enemy)を行います。
            if bullet.rect.colliderect(enemy.rect):
                # removeは指定した要素を一覧から外す操作です。
                # bullets.removeは当たった弾を、Battleが管理する元の弾一覧から外します。
                # 以後、Battleはbulletsから外したbulletを移動・描画しません。
                bullets.remove(bullet)
                # enemies.removeは当たった敵を、Battleが管理する元の敵一覧から外します。
                # 以後、Battleはenemiesから外したenemyを移動・描画しません。
                enemies.remove(enemy)
                # hit_enemiesが命中後も同じ弾で別の敵への命中を調べ続けると、重なった場合に同じ弾を2回removeしてエラーになります。
                # breakは内側のfor enemy in enemies[:]（選んだ弾に重なる敵を探す繰り返し）だけを終えます。
                # 外側のfor bullet in bullets[:]は続き、hit_enemiesは次の弾についてenemiesに残っている敵を調べます。
                break
```

### `Battle` が判定を実行する場所

`self.bullets` は `Battle` が管理する自機の弾の一覧、`self.enemies` は敵の一覧です。`hit_enemies(self.bullets, self.enemies)` の括弧の中で、この2つの一覧を指定します。`hit_enemies` の中の `bullets` と `enemies` は、それぞれこの元の一覧を指します。新しい弾や敵を作る指定ではありません。

このコードの元ファイル：[battle.py 43〜57行](./src/battle.py#L43-L57)。

```python
    # 移動と命中の処理が各所に分かれると、移動の前と後のどちらで判定するか追いにくいため、update（状態の更新）へ順序をまとめます。
    def update(self):
        # Game.runから依頼されたBattle.updateがget_pressed（押しているキーの状態）を調べ、Player.moveへ指定して自機を動かします。
        # スペースキーを押した知らせへの対応は、別のBattle.handle_eventが行います。
        self.player.move(pygame.key.get_pressed())

        # Battle.updateが自機の弾一覧self.bulletsをmove_bulletsへ指定し、弾の移動と画面外の弾の削除を依頼します。
        self.move_bullets(self.bullets)

        # Battle.updateがupdate_enemiesへ、敵の移動と画面外の敵の削除を依頼します。
        self.update_enemies()

        # hit_enemiesが、移動後に残った自機の弾と敵の重なりを調べ、命中した弾と敵を元のself.bullets/self.enemiesから外します。
        # Battle.updateは命中の戻り値を使わず、一覧の変更をhit_enemiesへ任せます。
        hit_enemies(self.bullets, self.enemies)
```

`Battle.update` は自機を移動し、`move_bullets` で弾を移動して画面外の弾を一覧から外し、`update_enemies` で敵を移動して画面外の敵を一覧から外したあと、`hit_enemies` を実行します。弾・敵の移動と画面外の削除は[battle.py 59〜81行](./src/battle.py#L59-L81)で確認してください。`hit_enemies` が調べるのは、移動後に一覧へ残っている弾と敵です。

### 長方形が重なると命中する

`bullet.rect` は弾の位置・大きさを表す長方形、`enemy.rect` は敵の位置・大きさを表す長方形です。`rect` はrectangle（長方形）の略です。弾は幅6・高さ20ピクセル（[player.py 44〜47行](./src/player.py#L44-L47)）、敵は幅40・高さ40ピクセル（[enemy.py 16〜23行](./src/enemy.py#L16-L23)）です。弾・敵は長方形で描かれるため、この章ではその長方形どうしで命中を調べます。描画する場所は[bullet.py 33〜35行](./src/bullet.py#L33-L35)と[enemy.py 43〜49行](./src/enemy.py#L43-L49)です。

`bullet.rect.colliderect(enemy.rect)` の `colliderect` は、2つの長方形の重なりを調べる操作です。`colliderect` は面積を持って重なる場合に `True`（成り立つ）、離れている場合や辺が接するだけの場合に `False`（成り立たない）を返します。`if` は、`colliderect` の結果が `True` のときだけ、下の削除を行います。`colliderect` 自体は、弾や敵を一覧から外しません。

このコードの元ファイル：[collisions.py 14〜30行](./src/collisions.py#L14-L30)。

```python

            # colliderectは2つの長方形の重なりを調べる操作です。
            # 弾と敵の長方形が面積を持って重なるとcolliderectはTrue（成り立つ）を返します。
            # 弾と敵の長方形の辺が接するだけか、弾と敵の長方形が離れている場合、colliderectはFalse（成り立たない）を返します。
            # ifはbullet.rect.colliderect(enemy.rect)がTrueのときだけ、bullets.remove(bullet)とenemies.remove(enemy)を行います。
            if bullet.rect.colliderect(enemy.rect):
                # removeは指定した要素を一覧から外す操作です。
                # bullets.removeは当たった弾を、Battleが管理する元の弾一覧から外します。
                # 以後、Battleはbulletsから外したbulletを移動・描画しません。
                bullets.remove(bullet)
                # enemies.removeは当たった敵を、Battleが管理する元の敵一覧から外します。
                # 以後、Battleはenemiesから外したenemyを移動・描画しません。
                enemies.remove(enemy)
                # hit_enemiesが命中後も同じ弾で別の敵への命中を調べ続けると、重なった場合に同じ弾を2回removeしてエラーになります。
                # breakは内側のfor enemy in enemies[:]（選んだ弾に重なる敵を探す繰り返し）だけを終えます。
                # 外側のfor bullet in bullets[:]は続き、hit_enemiesは次の弾についてenemiesに残っている敵を調べます。
                break
```

次の表は、弾1発と敵1機だけを調べる場合に、判定する瞬間の位置を説明する例です。実際の初期配置を変更する指示ではありません。横の位置は右へ、縦の位置は下へ行くほど数値が増えます。敵の左端140・右端180・上端60・下端100に対し、弾の左端157・右端163を共通にして、弾の上端と下端だけを変えています。すべてピクセル単位です。

| 判定する瞬間の弾の上端・下端 | 敵との位置関係 | `colliderect` の結果と `hit_enemies` の処理 |
| --- | --- | --- |
| 上端101・下端121 | 敵の下端100から離れている | `colliderect` は `False` を返し、`hit_enemies` はこの弾と敵を一覧へ残す |
| 上端100・下端120 | 弾の上端と敵の下端が100で接するだけ | `colliderect` は `False` を返し、`hit_enemies` はこの弾と敵を一覧へ残す |
| 上端99・下端119 | 横方向で重なり、縦方向でも99〜100の幅で重なる | `colliderect` は `True` を返し、`hit_enemies` はこの弾と敵を一覧から外す |

辺が接するだけでは重ならない仕様は、[pygame-ce公式のRectの説明](https://pyga.me/docs/ref/rect.html#pygame.Rect.colliderect)でも確認できます。

### コピーするのは一覧で、弾や敵は同じもの

`bullets[:]` の `[:]` は弾の一覧をコピーする書き方です。`bullets[:]` の各要素は、元の `bullets` と同じ弾を指します。`enemies[:]` も敵の一覧だけをコピーし、各要素は同じ敵を指します。該当する2つの `for` は[collisions.py 6〜13行](./src/collisions.py#L6-L13)で確認してください。`for` は一覧から要素を順に1つずつ選び、下に字下げした処理を繰り返します。

弾の一覧が「弾A・弾B・弾C」のとき、元の一覧を直接読んで弾Aを外すと、弾Bが前へ詰まります。そのまま次の位置を読む繰り返しでは、弾Bを飛ばして弾Cへ進みます。`bullets[:]` のコピーには「弾A・弾B・弾C」の並びが残るため、`hit_enemies` は弾Aを元の一覧から外したあとも、弾B、弾Cの順に調べられます。

`enemies[:]` を作るのは、外側の繰り返しが弾を1発選ぶたびです。弾Aで敵Xを元の敵一覧から外した場合、弾Bのために作る敵一覧のコピーには敵Xが入りません。`hit_enemies` は倒した敵を次の弾で再び調べません。

### 命中した弾で、別の敵を探し続けない

`remove` は指定した要素を一覧から外す操作です。`bullets.remove(bullet)` は命中した弾を元の弾一覧から外し、`enemies.remove(enemy)` は命中した敵を元の敵一覧から外します。削除と `break` は[collisions.py 19〜30行](./src/collisions.py#L19-L30)で確認してください。

`hit_enemies` が命中後も同じ弾で敵を探し続けると、別の敵にも重なっていた場合、すでに一覧から外した弾をもう一度 `remove` しようとしてエラーになります。`break` は内側の「今選んでいる弾に重なる敵を探す」繰り返しだけを終えます。外側の「弾を1発ずつ選ぶ」繰り返しは続くため、`hit_enemies` は次の弾について残っている敵を調べます。

1発の弾が同時に複数の敵へ重なった場合、`hit_enemies` は敵一覧の順で最初に見つけた1機だけを外します。その後、`break` でその弾の敵探しを終えます。どの敵にも重ならない弾は、元の弾一覧へ残ります。

### 一覧から外した弾と敵が、画面から消えるまで

`hit_enemies` は元の弾一覧と敵一覧をその場で変更します。`Battle.update` は、戻り値で命中を受け取って削除するのではなく、`hit_enemies` に一覧の変更を任せています。`hit_enemies` に `return` はなく、Pythonは処理が終わると `None` という特別な値を呼び出す側へ返します。`Battle.update` は `None` を使いません。`Game.run` が `Battle.draw` を呼び出し、`Battle.draw` が変更済みの `self.bullets`（自機の弾の一覧）と `self.enemies`（敵の一覧）を描画に使います。

このコードの元ファイル：[battle.py 83〜104行](./src/battle.py#L83-L104)。

```python
    # 一覧の変更と画面へ絵を描く処理を混ぜないよう、draw（描画）へ背景・自機・弾・敵を描く順序をまとめます。
    def draw(self, screen):
        # screenはGame.runが指定した描画先です。fill（塗る）が全体を暗い青に塗り、前に描いた絵を塗りつぶします。
        # (10, 10, 30)は赤・緑・青の強さの順で各値は0〜255です。fillは物体の位置や一覧を変更しません。
        screen.fill((10, 10, 30))

        # Battle.drawがPlayer.drawへ同じ描画先screenを指定し、現在の自機の位置に水色の三角形を描くよう依頼します。
        self.player.draw(screen)
        # Battle.drawがdraw_bulletsへ描画先screenと自機の弾一覧self.bulletsを指定し、残った弾の描画を依頼します。
        self.draw_bullets(screen, self.bullets)

        # forが、移動や命中の確認後に元の敵一覧self.enemiesへ残った敵を1機ずつenemyへ選びます。
        for enemy in self.enemies:
            # 選んだ敵のEnemy.drawが、同じ描画先screenへ現在の敵の位置に赤い長方形を描きます。
            enemy.draw(screen)

    # 弾1発を描くBullet.drawと、弾一覧を順に描く役割を分けるため、draw_bullets（弾の描画）へ繰り返しをまとめます。
    def draw_bullets(self, screen, bullets):
        # screenは呼び出す側が指定した描画先、bulletsは指定した弾一覧です。forが一覧に残った弾を1発ずつbulletへ選びます。
        for bullet in bullets:
            # bullet.draw(screen)が、選んだ弾bulletに保存した位置・大きさ・色で描画先screenへ弾を描きます。弾を移動したり一覧へ追加したりはしません。
            bullet.draw(screen)
```

`Battle.draw` は、まず背景を塗って前の絵を消し、元の弾一覧と敵一覧へ残っているものだけを描きます。命中して一覧から外れた弾と敵は、次の描画から対象に入りません。弾・敵を一覧から外す操作が、画面の絵を直接消すわけではありません。

このコードの元ファイル：[game.py 47〜54行](./src/game.py#L47-L54)。

```python
            # Game.runが今の戦闘self.battleのupdate（状態を更新する）へ、自機・敵・弾の移動、画面外の弾と敵の削除、弾と敵の命中の確認を依頼します。
            self.battle.update()

            # Game.runが今の戦闘self.battleのdraw（描く）へ、描画先self.screenに背景・自機・残っている弾と敵を描くよう依頼します。
            self.battle.draw(self.screen)

            # pygame.display.flip()が、self.screenへ描画済みの背景・自機・残っている弾と敵をゲームのウィンドウへ表示します。
            pygame.display.flip()
```

`Game.run` は `Battle.update` で位置と一覧を更新し、`Battle.draw` に描画を依頼したあと、`pygame.display.flip()` で描画済みの画面を表示します。命中した弾と敵が画面から消えるのは、この順で一覧の変更が画面へ反映されるためです。
