# Pg17. pygame「戻るボタンを作る」

Pg16でクリア画面は出るようになりました。

でも今は、

> **「クリアした。で、ここから何も押せんの？？？」**

状態です。

今回は、クリア画面に **BACKボタン** を置きます。

ただしpygameには、tkinterみたいな

```python
Button(...)
```

を置けば終わり、という仕組みはありません。

> **「ボタンって四角描いて文字乗せて、押した場所調べてるだけなん？？？」**

そうです。

まずはそこを見ます。

---

## Pg17-1. 今回使うもの

[back_button.py](./back_button.py) を開いてください。

Pg16のゲームに、

- ボタン用のRect
- ボタンの四角
- BACKという文字
- マウスクリック判定
- 押した後の画面切り替え

を追加します。

---

## Pg17-2. まずクリックできる四角を作る

最初に、

```python
back_button = pygame.Rect(
    220,
    330,
    200,
    60
)
```

とします。

これは、

```text
左から220
上から330
幅200
高さ60
```

の四角です。

ここで大事なのは、

> **まだこれは「見た目」ではありません。**

Rectは、

> **「この範囲をボタンとして使う」**

ための当たり判定用の四角です。

---

## Pg17-3. ボタンの見た目を描く

クリア画面で、

```python
pygame.draw.rect(
    screen,
    (70, 90, 180),
    back_button,
    border_radius=8
)
```

と描きます。

これで画面上に四角が見えます。

でも、まだただの四角です。

> **「これだけ見せられてBACKボタンだと察しろは無理やろ！」**

なので文字を載せます。

---

## Pg17-4. 四角の真ん中にBACKを書く

```python
back_text = button_font.render(
    "BACK",
    True,
    (255, 255, 255)
)
```

で文字を作ります。

そして、

```python
back_text_rect = back_text.get_rect(
    center=back_button.center
)
```

とします。

`back_button.center` は、

> **ボタンRectの真ん中**

です。

その位置へ文字の中心を合わせれば、

```python
screen.blit(
    back_text,
    back_text_rect
)
```

でボタンらしい見た目になります。

---

## Pg17-5. クリックされたことを受け取る

マウスを押すと、

```python
pygame.MOUSEBUTTONDOWN
```

というイベントが来ます。

今回は左クリックだけ使うので、

```python
if (
    event.type == pygame.MOUSEBUTTONDOWN
    and event.button == 1
):
    ...
```

とします。

`event.button == 1` は左クリックです。

---

## Pg17-6. 「どこ押したん？」を調べる

クリックされたからといって、

画面のどこを押してもBACK扱いにしたら困ります。

そこで、

```python
back_button.collidepoint(event.pos)
```

を使います。

`event.pos` には、

> **クリックした場所の座標**

が入っています。

つまり、

```python
if back_button.collidepoint(event.pos):
    game_state = "menu"
```

は、

> **BACKボタンの四角の中を押したらmenuへ切り替える**

という意味です。

---

## Pg17-7. クリア画面のときだけ反応させる

今回のコードでは、

```python
if (
    event.type == pygame.MOUSEBUTTONDOWN
    and event.button == 1
    and game_state == "clear"
):
```

としています。

これで、ゲーム中にたまたま同じ座標をクリックしても反応しません。

> **ボタン見えてないのに押せるんかい！！！**

を防いでいます。

画面によって使える操作を分ける、という考え方です。

---

## Pg17-8. 戻り先は仮のMENU画面

まだタイトル画面は作っていません。

なので今回は、

```python
game_state = "menu"
```

という仮の状態を1つ用意します。

BACKを押すと、

```text
GAME CLEAR
↓
BACKをクリック
↓
MENU
```

と切り替わります。

このMENUは完成形ではありません。

> **今は「ボタンを押したら別画面へ行けた」を確認するための仮画面です。**

タイトル画面は後の章でちゃんと作ります。

---

## Pg17-9. pygameのボタンの正体

今回やったことを並べると、

```text
Rectを作る
↓
四角を描く
↓
文字を載せる
↓
マウスクリックを受け取る
↓
クリック位置がRectの中か調べる
↓
押されていたら処理する
```

です。

つまり、

> **pygameのボタンは「専用部品」ではなく、自分でボタンっぽく組み立てている。**

ということです。

これが分かれば、

- 戻る
- 再開
- 始める
- タイトルへ戻る

なども同じ考え方で作れます。

---

## Pg17-10. 次はゲームオーバー画面

クリアしたときの画面と、

そこから押せるボタンは作れました。

でも負けたときはまだ、

> **HP 0になった瞬間ゲーム閉じるんかい！！！**

です。

次は、HPが0になったときに

> **GAME OVER**

と分かる専用画面へ切り替えます。
