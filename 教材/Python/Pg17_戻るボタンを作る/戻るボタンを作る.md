# Pg17. pygame「戻るボタンを作る」

Pg16でクリア画面は出るようになりました。

でも今は、

> **「クリアした。で、ここから何も押せんの？？？」**

状態です。

今回は、クリア画面に **BACKボタン** を置きます。

ただしpygameには、tkinterみたいな

```python
Button(...)
```

を置けば終わり、という仕組みはありません。

> **「ボタンって四角描いて文字乗せて、押した場所調べてるだけなん？？？」**

そうです。

まずはそこを見ます。

---

## Pg17-1. 今回使うもの

[back_button.py](./back_button.py) を開いてください。

Pg16のゲームに、

- ボタン用のRect
- ボタンの四角
- BACKという文字
- マウスクリック判定
- 押した後の画面切り替え

を追加します。

---

## Pg17-2. まずクリックできる四角を作る

最初に、

```python
back_button = pygame.Rect(
    220,
    330,
    200,
    60
)
```

とします。

これは、

```text
左から220
上から330
幅200
高さ60
```

の四角です。

ここで大事なのは、

> **まだこれは「見た目」ではありません。**

Rectは、

> **「この範囲をボタンとして使う」**

ための当たり判定用の四角です。

---

## Pg17-3. ボタンの見た目を描く

クリック範囲の `back_button` は作りましたが、Rectを作っただけでは画面には見えません。

クリア画面で、

```python
pygame.draw.rect(
    screen,
    (70, 90, 180),
    back_button,
    border_radius=8
)
```

と描きます。

`pygame.draw.rect()` に渡しているものを順番に見ると、

```text
screen
→ どの画面へ描くか

(70, 90, 180)
→ 何色で描くか

back_button
→ どの位置・大きさの四角を描くか

border_radius=8
→ 角をどれくらい丸めるか
```

です。

### `(70, 90, 180)` はボタンの色

色はRGBで、赤・緑・青の順です。

```text
赤 = 70
緑 = 90
青 = 180
```

各値は0〜255で、青が一番強いので青系のボタンになります。

この70・90・180は色の強さで、座標や大きさではありません。

### `back_button` は位置と大きさ

`back_button` はPg17-2で作った、

```python
pygame.Rect(220, 330, 200, 60)
```

です。

そのため、ここで描かれる四角も、

```text
左から220
上から330
幅200
高さ60
```

になります。

クリック判定と見た目で同じ `back_button` を使うので、見えているボタンとクリックできる範囲を揃えられます。

### `border_radius=8` は角の丸み

`border_radius` は、四角の角を丸める半径です。

```text
border_radius=8
→ 半径8ピクセルで角を丸める

border_radius=0
→ 角を丸めない
```

という違いです。

これで画面上に青い角丸の四角が見えます。

でも、まだただの四角です。

> **「ただの四角が戻るだと思わんわ」**

なので文字を載せます。

### ボタンの色を変えてみる

`back_button.py` の **171行目** を変更します。

VS Codeで **Ctrl + F**、macOSでは **Command + F** を押して、

```text
(70, 90, 180),
```

を検索してください。

変更前:

```python
(70, 90, 180),
```

変更後:

```python
(180, 90, 70),
```

保存してゲームを実行し、クリア画面を表示してください。

ボタンが青系から赤茶系へ変われば成功です。

確認したら `(70, 90, 180)` に戻してください。

### 角の丸みを変えてみる

`border_radius` は **173行目** です。

Ctrl + F、macOSではCommand + Fで、

```text
border_radius=8
```

を検索してください。

変更前:

```python
border_radius=8
```

変更後:

```python
border_radius=0
```

保存して再実行し、クリア画面のボタンの角が四角くなれば成功です。

確認したら `border_radius=8` に戻してください。

## Pg17-4. 四角の真ん中にBACKを書く

ボタンの上へ `BACK` の文字を載せます。

まず、

```python
back_text = button_font.render(
    "BACK",
    True,
    (255, 255, 255)
)
```

で文字画像を作ります。

`button_font` はファイルの **17行目** で、

```python
button_font = pygame.font.Font(None, 40)
```

として用意しています。

`None` はpygameの標準フォント、`40` は文字サイズです。

`button_font.render()` に渡しているものは、

```text
"BACK"
→ 表示する文章

True
→ 文字の縁を滑らかにする指定

(255, 255, 255)
→ 文字色
```

です。

`(255, 255, 255)` はRGBがすべて最大なので白です。

`render()` の結果は**文字画像**で、その画像が `back_text` に入ります。

この時点ではまだ画面へ描いていません。

次に、

```python
back_text_rect = back_text.get_rect(
    center=back_button.center
)
```

で文字画像の位置を決めます。

`back_text.get_rect()` は、`back_text` と同じ幅・高さのRectを作ります。

`back_button.center` は、Pg17-2で作ったボタンRectの中心座標です。

```python
center=back_button.center
```

とすることで、**文字画像のRectの中心を、ボタンRectの中心へ合わせます**。

`get_rect()` は位置を決めるだけで、まだ文字画像を描きません。

最後に、

```python
screen.blit(
    back_text,
    back_text_rect
)
```

で、`back_text` を `back_text_rect` の位置へ実際に描きます。

つまり、

```text
render()
→ BACKの文字画像を作る
↓
get_rect(center=back_button.center)
→ 文字画像の中心をボタンの中心へ合わせる
↓
blit()
→ 文字画像をscreenへ描く
```

という順番です。

### 文字を少し上へずらしてみる

`back_button.py` の **187行目** を変更します。

Ctrl + F、macOSではCommand + Fで、

```text
center=back_button.center
```

を検索してください。

変更前:

```python
center=back_button.center
```

変更後:

```python
center=(back_button.centerx, back_button.centery - 8)
```

`back_button.centerx` はボタン中心のx、`back_button.centery` は中心のyです。

yから8を引くので、文字だけ8ピクセル上へ移動します。

保存して再実行し、`BACK` の文字がボタン中央より少し上へ移動すれば成功です。

確認したら `center=back_button.center` に戻してください。

## Pg17-5. クリックされたことを受け取る

マウスを押すと、

```python
pygame.MOUSEBUTTONDOWN
```

というイベントが来ます。

今回は左クリックだけ使うので、

```python
if (
    event.type == pygame.MOUSEBUTTONDOWN
    and event.button == 1
):
    ...
```

とします。

`event.button == 1` は左クリックです。

ここではまだ、画面のどこを押したかまでは判定していません。

---

## Pg17-6. 「どこ押したん？」を調べる

クリックされたからといって、画面のどこを押してもBACK扱いにしたら困ります。

そこで、

```python
back_button.collidepoint(event.pos)
```

を使います。

`event.pos` には、クリックした場所の、

```text
(x座標, y座標)
```

が入っています。

`back_button` は、

```python
pygame.Rect(220, 330, 200, 60)
```

で作ったボタンの四角です。

`collidepoint()` は、その四角の中に `event.pos` の点が入っているかを調べます。

```text
ボタンの中をクリックした
→ True

ボタンの外をクリックした
→ False
```

です。

そのため、

```python
if back_button.collidepoint(event.pos):
    game_state = "menu"
```

は、

> **クリックした点がBACKボタンの四角の中なら、menuへ切り替える**

という意味です。

`False` の場合は `if` の中へ入らないので、ボタンの外をクリックしても画面は切り替わりません。

---

## Pg17-7. クリア画面のときだけ反応させる

今回のコードでは、

```python
if (
    event.type == pygame.MOUSEBUTTONDOWN
    and event.button == 1
    and game_state == "clear"
):
```

としています。

これで、ゲーム中にたまたま同じ座標をクリックしても反応しません。

> **ボタン見えてないのに押せるんかい！！！**

を防いでいます。

画面によって使える操作を分ける、という考え方です。

## Pg17-8. 戻り先は仮のMENU画面

まだタイトル画面は作っていません。

なので今回は、

```python
game_state = "menu"
```

という仮の状態を1つ用意します。

BACKを押すと、

```text
GAME CLEAR
↓
BACKをクリック
↓
MENU
```

と切り替わります。

このMENUは完成形ではありません。

> **今は「ボタンを押したら別画面へ行けた」を確認するための仮画面です。**

タイトル画面の完成版は、ゲームの画面構成を扱う章で作成します。

---

## Pg17-9. pygameのボタンの正体

今回やったことを並べると、

```text
Rectを作る
↓
四角を描く
↓
文字を載せる
↓
マウスクリックを受け取る
↓
クリック位置がRectの中か調べる
↓
押されていたら処理する
```

です。

つまり、

> **pygameのボタンは「専用部品」ではなく、自分でボタンっぽく組み立てている。**

ということです。

これが分かれば、

- 戻る
- 再開
- 始める
- タイトルへ戻る

なども同じ考え方で作れます。
