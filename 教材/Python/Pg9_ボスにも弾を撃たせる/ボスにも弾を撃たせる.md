# Pg9. pygame「ボスにも弾を撃たせる」

Pg8で、ついにボスが出るようになりました。

HPも50あります。

見た目もデカいです。

……でも、

> **「ボス出たけどなんもしてこんやんけ！！！」**

ただそこにいるだけです。

これではデカい的が増えただけです。

今回は、ボスにも攻撃させます。

そして実際に遊んでみます。

---

## Pg9-1. 今回作るもの

[boss_attack.py](./boss_attack.py) を開いてください。

今回追加するのは、ボス専用の弾です。

```text
ボスが出る
↓
ボスが弾を撃つ
↓
弾が下へ飛ぶ
↓
プレイヤーに当たる
```

これで、やっとボスが「攻撃してくる相手」になります。

---

## Pg9-2. ボス専用の弾を用意する

```python
boss_bullets = []
boss_bullet_speed = 4
boss_fire_interval = 60
boss_fire_timer = 0
```

通常敵の弾とは別に、ボス弾を管理します。

仕組み自体はPg6でやった敵弾とほぼ同じです。

---

## Pg9-3. ボスが出たら撃つ

ボスが出た瞬間に、

```python
bullets.clear()

boss_bullets.append([
    boss_x,
    boss_y + 40
])
```

として、最初の1発を撃たせます。

その後は、

```python
boss_fire_timer = boss_fire_timer + 1

if boss_fire_timer >= boss_fire_interval:
    boss_bullets.append([
        boss_x,
        boss_y + 40
    ])
    boss_fire_timer = 0
```

で、一定間隔ごとに撃ちます。

---

## Pg9-4. ボス弾を下へ動かす

```python
for boss_bullet in boss_bullets:
    boss_bullet[1] = boss_bullet[1] + boss_bullet_speed
```

通常敵の弾と同じで、yを増やせば下へ進みます。

ここまでは普通です。

---

## Pg9-5. じゃあ遊んでみる

ボスも撃つようになりました。

これでやっとボス戦らしくなったので、実際に遊んでみます。

……

> **「いやデカすぎ！！！避ける場所ないやん！！！」**

はい。

今度は別の問題が出ました。

---

## Pg9-6. 問題の数字

今回の主犯はこれです。

```python
boss_bullet_width = 700
boss_bullet_height = 80
```

画面は640×480です。

その中で弾1発が、

```text
横 700
縦 80
```

あります。

横幅が画面そのものよりデカいです。

> **そりゃ左右に逃げても避けられんわ。**

---

## Pg9-7. 速度は普通

```python
boss_bullet_speed = 4
boss_fire_interval = 60
```

なので、

- 異常な超高速弾ではない
- ものすごい弾幕でもない
- **ただ弾がデカすぎる**

という状態です。

原因を1つに絞ってあります。

---

## Pg9-8. 巨大弾を描く

```python
pygame.draw.rect(
    screen,
    (255, 80, 80),
    (
        boss_bullet[0] - boss_bullet_width // 2,
        boss_bullet[1],
        boss_bullet_width,
        boss_bullet_height
    )
)
```

横700なので、画面を横断する壁みたいな弾になります。

高さは80なので、生成した瞬間にプレイヤーへ当たって消えるのではなく、

> **壁が上から降りてくる**

のをちゃんと見られます。

---

## Pg9-9. 当たり判定も同じ大きさ

```python
boss_bullet_rect = pygame.Rect(
    boss_bullet[0] - boss_bullet_width // 2,
    boss_bullet[1],
    boss_bullet_width,
    boss_bullet_height
)
```

として、見た目と同じサイズで判定します。

見た目だけ巨大で当たり判定だけ小さい、ということにはしません。

だから本当に避けられません。

---

## Pg9-10. 実装としては正しい

このコードは、

- ボスが弾を撃つ
- 弾が動く
- 当たり判定がある
- HPが減る

ので、機能としては動いています。

でも、

> **「動く」と「遊べる」は別です。**

これが今回の本題です。

---

## Pg9-11. 数字を変えただけでクソゲーになる

ボス攻撃の仕組み自体は普通です。

それでも、

```python
boss_bullet_width = 700
boss_bullet_height = 80
```

という数字だけでゲーム性は壊れました。

つまり、

> **パラメータもゲームの一部**

です。

---

## Pg9-12. この章では直さない

ここで普通サイズへ直したくなります。

でも今回はまだ直しません。

まずは、

```text
ボスが攻撃してこない
↓
攻撃を実装する
↓
遊んでみる
↓
今度は弾がデカすぎる
↓
何が悪いか確認する
```

までを体験します。

---

## Pg9-13. CIも「失敗状態」を守る

普通なら、巨大すぎる弾はCIで止めたいところです。

でもPg9だけは逆です。

Pg9のCIでは、

> **ちゃんと画面を覆うほど弾がデカいこと**

を確認します。

うっかり普通サイズへ直してしまうとCIが落ちます。

教材として、

> **意図的な失敗例を失敗例のまま保存する**

ためです。

---

## Pg9-14. 次で直す

次のPg10では、

> **「いやこれ避けられんわ。直そ」**

から始めます。

ボスHPはPg9もPg10も同じ `50` のままです。

主に弾サイズを直すことで、

> **同じボスでもパラメータ次第で遊びやすさが変わる**

ことを比べます。

---

## Pg9-15. ここまでで覚えること

1. ボスも通常敵と同じように弾を撃たせられる
2. ボス弾もリストで複数管理できる
3. ボス弾もyを増やせば下へ動く
4. 実装してから遊ぶと、別の問題が見つかることがある
5. 弾サイズと当たり判定サイズはゲームバランスに直結する
6. 動くコードでも遊べないゲームになることがある
7. パラメータもゲームの一部
8. 意図的な失敗例も教材として価値がある
