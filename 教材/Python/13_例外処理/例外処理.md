# 13. 例外処理

この章では、**入力ミスやファイル不足が起きても、プログラムをその場で終わらせない方法**を学びます。

今回作るのは、数字以外を入力しても異常終了せず、利用者へメッセージを表示する小さなプログラムです。

---

## 13-1. 今回作るもの

まず、利用者に数字を入力してもらいます。

```text
数字を入力してください: 10
```

なら、

```text
2倍すると 20 です
```

と表示します。

でも、

```text
数字を入力してください: ねこ
```

と入力された場合は、

```text
数字を入力してください
```

と表示して終了します。

---

## 13-2. なぜ例外処理が必要なの？

4章では、次のようなコードを使いました。

```python
number = int(input("数字を入力してください: "))
```

利用者が `10` と入力すれば問題ありません。

でも、

```text
ねこ
```

と入力すると、Pythonは数値へ変換できず、エラーで止まります。

> **「1文字ミスっただけでアプリごと死ぬな！」**

となります。

実際のプログラムでは、

- 数字のはずなのに文字が入力された
- ファイルが存在しなかった
- 必要なデータが見つからなかった

など、想定外のことが起こります。

そこで使うのが **例外処理** です。

---

## 13-3. サンプルコード

[safe_number_input.py](./safe_number_input.py) を開いてください。

`safe` は「安全な」、`number` は「数字」、`input` は「入力」という意味です。

```python
text = input("数字を入力してください: ")

try:
    number = int(text)
except ValueError:
    print("数字を入力してください")
else:
    print("2倍すると", number * 2, "です")
```

---

## 13-4. `try` とは

`try` は、

> まず、この処理を試してみる

という意味です。

```python
try:
    number = int(text)
```

ここでは、入力された文字を整数へ変換しようとしています。

---

## 13-5. `except` とは

もし `try` の中で特定の例外が起きたら、`except` 側を実行します。

```python
except ValueError:
    print("数字を入力してください")
```

`int("ねこ")` のように、数値へ変換できない文字を渡すと `ValueError` が発生します。

そのとき、

```text
数字を入力してください
```

と表示します。

---

## 13-6. 例外とは？

Pythonでは、実行中に起きる問題の一部を **例外** と呼びます。

たとえば、

```python
int("ねこ")
```

では `ValueError`、

```python
open("not_found.txt", "r")
```

では `FileNotFoundError`

が起こることがあります。

例外処理では、

> どんな問題が起きたか

に合わせて処理を分けられます。

---

## 13-7. エラーと例外は何が違うの？

初学者のうちは、どちらも「プログラムがうまく動かない原因」と考えて構いません。

ただし、例外処理で扱えるのは主に**実行中に発生する例外**です。

たとえば、書き方そのものを間違えた構文エラーは、基本的にはコードを直す必要があります。

```text
書き方が間違っている
→ コードを直す

入力やファイル状態によって起こる問題
→ 例外処理で対応できる場合がある
```

という違いです。

---

## 13-8. `else` は成功したとき

今回のサンプルでは、

```python
else:
    print("2倍すると", number * 2, "です")
```

も使っています。

`else` は、`try` の中で例外が起きなかったときに実行されます。

つまり、

```text
変換成功
→ else

変換失敗
→ except
```

です。

---

## 13-9. `finally` もある

`finally` は、成功しても失敗しても最後に実行したい処理を書くために使います。

```python
try:
    print("処理中")
except ValueError:
    print("失敗")
finally:
    print("終了します")
```

今回は必須ではありません。

今は、

> `finally` は最後に必ず行いたい処理

くらいに覚えておけば十分です。

---

## 13-10. ファイルが無い場合にも使える

12章では、

```python
open("not_found.txt", "r", encoding="utf-8")
```

でファイルが存在しないと止まると説明しました。

例外処理を使えば、

```python
try:
    with open("not_found.txt", "r", encoding="utf-8") as file:
        text = file.read()
except FileNotFoundError:
    print("ファイルが見つかりません")
```

のようにできます。

---

## 13-11. 何でも `except:` にしない

次のような書き方もできます。

```python
try:
    number = int(text)
except:
    print("エラー")
```

でも、これはおすすめしません。

なぜなら、

> 何が原因で失敗したのか分からなくなる

からです。

できるだけ、

```python
except ValueError:
```

や、

```python
except FileNotFoundError:
```

のように、想定している例外を指定します。

---

## 13-12. 例外を握り潰さない

さらに良くないのが、

```python
try:
    number = int(text)
except:
    pass
```

です。

これだと、何か問題が起きても何も表示されません。

利用者からすると、

> 「押したのに何も起きないんだけど？」

となります。

例外処理は、エラーを消すためではありません。

**問題が起きたときに、どうするか決めるための仕組み**です。

---

## 13-13. GUIでも同じ

Tk3の電卓では、数字以外を入力すると `float()` でエラーになる可能性がありました。

そこでも、

```python
try:
    number = float(text)
except ValueError:
    result_label.config(text="数字を入力してください")
```

のように使えます。

つまり例外処理は、ターミナルでもGUIでも同じ考え方です。

---

## 13-14. 自分で変えてみる

表示メッセージを変えてみましょう。

```python
except ValueError:
    print("その文字は数字に変換できません")
```

また、入力した数字を3倍にしても構いません。

```python
print("3倍すると", number * 3, "です")
```

## 13-16. ここまでで覚えること

この章では、次のことが分かれば十分です。

1. 実行中に起きる問題の一部を例外と呼ぶ
2. `try` で問題が起きるかもしれない処理を試せる
3. `except` で特定の例外へ対応できる
4. `ValueError` は数値変換失敗などで起こる
5. `FileNotFoundError` はファイルが見つからないときに起こる
6. `else` は例外が起きなかったときに使える
7. `finally` は最後に必ず実行したい処理に使える
8. 何でも `except:` にせず、想定する例外を指定する
9. 例外処理は問題を隠すためではなく、問題が起きたときの動作を決めるために使う
