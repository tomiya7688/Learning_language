# Pg16. pygame「クリア画面を作る」

Pg14までで、ボスを倒せるシューティングゲームになりました。

でも今は、ボスを倒したらそのままゲームが終わります。

> **「ボス倒した瞬間ウィンドウ消えるんかい！！！」**

今回は、ボス撃破後に

> **GAME CLEAR!**

と分かる専用画面へ切り替えます。

難しい画面管理はまだやりません。

まずは、

```text
ゲーム中
↓
クリア画面
```

の2つだけ考えます。

---

## Pg16-1. 今回使うもの

[clear_screen.py](./clear_screen.py) を開いてください。

Pg14までのゲームをそのまま使い、

> **ボスを倒したあとだけ表示を切り替える**

ようにします。

移動、弾、敵、ボス、当たり判定などはそのままです。

## Pg16-2. 「今どの画面？」を変数で持つ

まず、

```python
game_state = "playing"
```

とします。

`state` は「状態」という意味です。

つまり、

```text
game_state = "playing"
↓
今はゲーム中
```

です。

今回はあとで、

```python
game_state = "clear"
```

にも変わります。

> **「今どの画面なん？」を変数1個で覚えておく**

くらいに考えてください。

---

## Pg16-3. ボスを倒したら終了ではなく状態を変える

Pg14までは、ボスHPが0になったらゲームループを終えていました。

Pg16では、

```python
if boss_active and boss_hp <= 0:
    game_state = "clear"
```

にします。

ここが今回の中心です。

```text
今まで
ボスを倒す
↓
ゲーム終了

Pg16
ボスを倒す
↓
game_state を clear にする
↓
クリア画面を表示する
```

です。

> **終わらせるんじゃなくて、画面を変える。**

これだけでかなりゲームらしくなります。

---

## Pg16-4. クリア中はゲームを動かさない

`game_state == "clear"` のときまで、

- 敵が動く
- 弾が動く
- ボスが撃つ

を続けたら変です。

なのでイベント処理のあとに、

```python
if game_state == "clear":
    # クリア画面を描く
    ...
    continue
```

とします。

`continue` が実行されると、その周回の残りを飛ばして次のループへ進みます。

つまり、

> **クリア画面なのに後ろで戦争続けるな！！！**

ということです。

ゲーム中の更新処理まで進ませません。

---

## Pg16-5. クリア画面を描く

クリア画面は、

```text
背景を塗る
↓
文字画像を作る
↓
文字画像の位置を決める
↓
文字画像をscreenへ描く
↓
画面へ反映する
```

という順番で作ります。

### 1. 背景を塗る

まず、

```python
screen.fill((8, 8, 24))
```

でゲーム画面全体を塗ります。

`screen` は、最初に `pygame.display.set_mode((640, 480))` で作ったゲーム画面です。

`fill()` は、その `screen` 全体を指定した色で塗りつぶします。

`(8, 8, 24)` はRGBです。

```text
赤 = 8
緑 = 8
青 = 24
```

各値は0〜255で、どれも小さいのでかなり暗く、青だけ少し強いので暗い青系の背景になります。

### 2. 文字の形と大きさを用意する

文字を作るための `clear_font` は、ファイルの **15行目** で、

```python
clear_font = pygame.font.Font(None, 72)
```

として用意しています。

```text
None
→ pygameの標準フォントを使う

72
→ 文字サイズ
```

です。

`clear_font` 自体は、まだ `GAME CLEAR!` という文字画像ではありません。

### 3. `render()` で文字画像を作る

次に、

```python
clear_text = clear_font.render(
    "GAME CLEAR!",
    True,
    (255, 240, 100)
)
```

で文字画像を作ります。

`clear_font.render()` に渡しているものは、

```text
"GAME CLEAR!"
→ 表示する文章

True
→ 文字の縁を滑らかにする指定

(255, 240, 100)
→ 文字色
```

です。

`(255, 240, 100)` もRGBです。

赤255・緑240が強く、青100なので、黄色系の文字になります。

`render()` が作った**文字画像**が `clear_text` に入ります。

この時点ではまだ `screen` へ描いていません。

### 4. 文字画像を描く

位置を決めたあと、

```python
screen.blit(
    clear_text,
    clear_text_rect
)
```

で文字画像を `screen` へ描きます。

```text
clear_text
→ 描く文字画像

clear_text_rect
→ その画像を置く位置
```

です。

`render()` で文字画像を作ることと、`blit()` で画面へ描くことは別の処理です。

### 5. 画面へ反映する

最後に、

```python
pygame.display.flip()
```

で、このフレームで `screen` へ描いた内容を実際の画面へ反映します。

### 背景色を変えてみる

`clear_screen.py` の **130行目** を変更します。

VS Codeで **Ctrl + F**、macOSでは **Command + F** を押して、

```text
screen.fill((8, 8, 24))
```

を検索してください。

変更前:

```python
screen.fill((8, 8, 24))
```

変更後:

```python
screen.fill((0, 0, 0))
```

保存してゲームを実行し、ボスを倒してクリア画面を表示してください。

背景が暗い青系から黒へ変われば成功です。

確認したら `(8, 8, 24)` に戻しておいてください。

## Pg16-6. 文字画像の位置をRectで決める

`render()` で作った `clear_text` は文字画像なので、画像と同じようにRectを使って位置を決められます。

```python
clear_text_rect = clear_text.get_rect(
    center=(320, 210)
)
```

`clear_text.get_rect()` は、`clear_text` と同じ幅・高さのRectを作ります。

そこへ、

```python
center=(320, 210)
```

と指定しています。

これは、**文字画像を囲うRectの中心**を、

```text
x = 320
y = 210
```

へ合わせる指定です。

画面は640×480なので、厳密な中央は、

```text
(320, 240)
```

です。

今回は `(320, 210)` なので、横方向は中央、縦方向は中央より30ピクセル上です。

つまり `GAME CLEAR!` は、**画面中央付近の少し上**へ置いています。

`center=(320, 210)` は固定した座標です。pygameが画面サイズから自動で中央を計算しているわけではありません。

また、`get_rect()` を呼んだだけでは文字は画面へ描かれません。

```text
clear_text.get_rect(...)
→ 文字画像と同じ大きさのRectを作り、位置を決める

screen.blit(clear_text, clear_text_rect)
→ その位置へ文字画像を実際に描く
```

という役割の違いがあります。

### 文字を少し下へ動かしてみる

`clear_screen.py` の **143行目** を変更します。

Ctrl + F、macOSではCommand + Fで、

```text
center=(320, 210)
```

を検索してください。

変更前:

```python
center=(320, 210)
```

変更後:

```python
center=(320, 240)
```

保存して再実行し、ボスを倒してクリア画面を表示してください。

`GAME CLEAR!` が30ピクセル下へ移動し、画面の厳密な中央付近に来れば成功です。

確認したら `center=(320, 210)` に戻しておいてください。

## Pg16-7. クリア中はSPACEを押しても撃たない

イベント処理では、

```python
if (
    event.key == pygame.K_SPACE
    and game_state == "playing"
):
    bullets.append([player_x, player_y - 20])
```

としています。

クリア画面でSPACEを押しても、

> **裏で弾だけ増えてるんだけど？？？**

とならないようにしています。

状態を切り替えたら、

- 更新
- 操作
- 描画

のどれを動かすかも意識します。
