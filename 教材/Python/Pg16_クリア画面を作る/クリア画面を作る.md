# Pg16. pygame「クリア画面を作る」

Pg14までで、ボスを倒せるシューティングゲームになりました。

でも今は、ボスを倒したらそのままゲームが終わります。

> **「ボス倒した瞬間ウィンドウ消えるんかい！！！」**

今回は、ボス撃破後に

> **GAME CLEAR!**

と分かる専用画面へ切り替えます。

難しい画面管理はまだやりません。

まずは、

```text
ゲーム中
↓
クリア画面
```

の2つだけ考えます。

---

## Pg16-1. 今回使うもの

[clear_screen.py](./clear_screen.py) を開いてください。

Pg14までのゲームをそのまま使い、

> **ボスを倒したあとだけ表示を切り替える**

ようにします。

移動、弾、敵、ボス、当たり判定などはそのままです。

---

## Pg16-2. 「今どの画面？」を変数で持つ

まず、

```python
game_state = "playing"
```

とします。

`state` は「状態」という意味です。

つまり、

```text
game_state = "playing"
↓
今はゲーム中
```

です。

今回はあとで、

```python
game_state = "clear"
```

にも変わります。

> **「今どの画面なん？」を変数1個で覚えておく**

くらいに考えてください。

---

## Pg16-3. ボスを倒したら終了ではなく状態を変える

Pg14までは、ボスHPが0になったらゲームループを終えていました。

Pg16では、

```python
if boss_active and boss_hp <= 0:
    game_state = "clear"
```

にします。

ここが今回の中心です。

```text
今まで
ボスを倒す
↓
ゲーム終了

Pg16
ボスを倒す
↓
game_state を clear にする
↓
クリア画面を表示する
```

です。

> **終わらせるんじゃなくて、画面を変える。**

これだけでかなりゲームらしくなります。

---

## Pg16-4. クリア中はゲームを動かさない

`game_state == "clear"` のときまで、

- 敵が動く
- 弾が動く
- ボスが撃つ

を続けたら変です。

なのでイベント処理のあとに、

```python
if game_state == "clear":
    # クリア画面を描く
    ...
    continue
```

とします。

`continue` が実行されると、その周回の残りを飛ばして次のループへ進みます。

つまり、

> **クリア画面なのに後ろで戦争続けるな！！！**

ということです。

ゲーム中の更新処理まで進ませません。

---

## Pg16-5. クリア画面を描く

まず背景を塗ります。

```python
screen.fill((8, 8, 24))
```

その上に、

```python
clear_text = clear_font.render(
    "GAME CLEAR!",
    True,
    (255, 240, 100)
)
```

で文字を作ります。

そして中央へ置きます。

```python
clear_text_rect = clear_text.get_rect(
    center=(320, 210)
)

screen.blit(
    clear_text,
    clear_text_rect
)
```

これでボス撃破後に専用画面が出ます。

---

## Pg16-6. 文字もRectで中央に置ける

画像と同じように、文字にもRectがあります。

```python
clear_text.get_rect(
    center=(320, 210)
)
```

とすると、

> **文字の中心を画面中央付近へ置く**

ことができます。

Pg14で画像に使った `get_rect()` と考え方は同じです。

---

## Pg16-7. クリア中はSPACEを押しても撃たない

イベント処理では、

```python
if (
    event.key == pygame.K_SPACE
    and game_state == "playing"
):
    bullets.append([player_x, player_y - 20])
```

としています。

クリア画面でSPACEを押しても、

> **裏で弾だけ増えてるんだけど？？？**

とならないようにしています。

状態を切り替えたら、

- 更新
- 操作
- 描画

のどれを動かすかも意識します。

---

## Pg16-8. 今回は2状態だけ

今回は、

```text
playing
clear
```

の2つだけです。

まだ、

- タイトル
- ゲームオーバー
- ポーズ
- 設定画面

まで全部まとめて考えません。

> **最初から画面20個管理しようとすんな！！！**

まず2つ切り替えられれば十分です。

この考え方は、この先のゲームオーバー画面やタイトル画面でも使えます。

---

## Pg16-9. ゲームロジックはほとんど変わっていない

今回追加した中心は、

```text
game_state
↓
playing / clear を切り替える
↓
表示する画面を変える
```

です。

敵のクラスも、

プレイヤー移動も、

当たり判定も、

背景スクロールもそのままです。

> **新しい画面を足すたびにゲーム全部作り直す必要はありません。**
