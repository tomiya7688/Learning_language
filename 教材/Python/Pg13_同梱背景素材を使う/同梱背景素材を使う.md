## Pg13-2. 画像を読み込む

背景画像の場所を作ったあと、そのファイルをpygameへ読み込みます。

```python
background_image = pygame.image.load(
    str(background_path)
).convert()
```

この3行は処理がつながっているので、内側から順番に見ます。

### `background_path`

`background_path` には、背景画像ファイルの**場所**が入っています。

まだ画像そのものではありません。

### `str(background_path)`

`background_path` は `Path` で作った「ファイルの場所」を表す値です。

```python
str(background_path)
```

で、その場所を文字列へ変えています。

このコードでは、その文字列を `pygame.image.load()` へ渡します。

### `pygame.image.load(...)`

```python
pygame.image.load(str(background_path))
```

で、指定した場所にあるPNG画像を読み込みます。

ここで初めて、画像ファイルの内容をpygameで扱える画像として読み込みます。

### `.convert()`

読み込んだ画像に続けて、

```python
.convert()
```

を呼んでいます。

`convert()` は、画像を**画面へ描きやすい内部形式**へ変換した画像を作ります。

ここでしているのは、pygameの中で扱う画像の形式を整えることです。

- 元の `space_background.png` ファイルを書き換えるわけではない
- 画像の幅や高さを変える処理ではない

という点に注意してください。

最後に、その画像が、

```python
background_image
```

へ入ります。

つまり、

```text
background_path
→ 画像ファイルの場所

background_image
→ 読み込んで使えるようにした画像
```

です。

## Pg13-3. 画像ファイルはどこにある？

背景画像の場所は、

```python
background_path = (
    Path(__file__).parent
    / "assets"
    / "space_background.png"
)
```

で作っています。

まず、

```python
Path(__file__).parent
```

は、**今動かしている `bundled_background.py` があるフォルダ**を表します。

そこへ、

```python
/ "assets"
/ "space_background.png"
```

をつないでいます。

`Path` で使っている `/` は、ここでは割り算ではありません。

**フォルダ名やファイル名をつなぐための記法**です。

そのため、このコードは、

```text
bundled_background.py があるフォルダ
└ assets
  └ space_background.png
```

という場所を作っています。

作った場所を `background_path` に入れ、その値をPg13-2の `image.load()` で使います。

こうして `.py` ファイル自身の場所を基準にすると、別のフォルダからPythonを起動した場合でも、同梱素材を見つけやすくなります。

## Pg13-4. ゲーム画面の大きさへ合わせる

読み込んだ同梱素材は160×120です。

ゲーム画面は640×480なので、そのままでは画面全体を覆いません。

そこで、

```python
background_image = pygame.transform.scale(
    background_image,
    (640, 480)
)
```

で画像の大きさを変更します。

`pygame.transform.scale()` に渡しているものは、

```text
background_image
→ 大きさを変更する画像

(640, 480)
→ 変更後の幅と高さ
```

です。

`640` と `480` は画像を置く座標ではありません。

```text
幅  = 640ピクセル
高さ = 480ピクセル
```

という**変更後の画像サイズ**です。

`scale()` は大きさを変えた新しい画像を返します。

その戻ってきた画像を、

```python
background_image = ...
```

でもう一度 `background_image` へ入れ直しています。

つまり、

```text
160×120のbackground_image
↓ scale()
640×480のbackground_image
```

になります。

### 大きさを一度変えて確認してみる

`bundled_background.py` の **32行目** を変更します。

VS Codeで **Ctrl + F**、macOSでは **Command + F** を押して、

```text
(640, 480)
```

を検索してください。

画面サイズを作る `(640, 480)` もあるので、**`pygame.transform.scale(` の中にある32行目**を変更します。

変更前:

```python
(640, 480)
```

変更後:

```python
(320, 240)
```

保存して再実行すると、背景画像自体が小さくなり、画面全体を覆わなくなります。

確認したら `(640, 480)` に戻してください。

この章の完成形では、ゲーム画面と同じ640×480へ拡大します。

## Pg13-5. 1枚だけだと穴が空く

背景画像を1枚だけ下へ動かすと、

```text
画像が下へ動く
↓
上側が空く
↓
真っ黒な穴が見える
```

となります。

> **「背景流したら後ろ真っ黒やん！！！」**

そこで同じ背景を2枚使います。

## Pg13-6. 背景を上下に2枚並べる

```python
background_y_1 = 0
background_y_2 = -480
```

とします。

最初は、

```text
2枚目  y = -480
────────────
1枚目  y = 0
────────────
画面下 y = 480
```

という並びです。

2枚目は画面のすぐ上で待っています。

---

## Pg13-7. 2枚とも下へ動かす

```python
background_y_1 = background_y_1 + background_speed
background_y_2 = background_y_2 + background_speed
```

とします。

Pg12では星1個ずつのy座標を動かしました。

Pg13では、

> **背景画像そのもののy座標**

を動かします。

やっている本質は同じです。

## Pg13-8. 下へ抜けた画像を上へ戻す

```python
if background_y_1 >= 480:
    background_y_1 = background_y_2 - 480

if background_y_2 >= 480:
    background_y_2 = background_y_1 - 480
```

とします。

1枚が画面下へ抜けたら、

> **もう1枚の上へつなぎ直す**

だけです。

これで、

```text
背景1
↓
背景2
↓
背景1
↓
背景2
↓
...
```

とずっと流れ続けます。

## Pg13-9. 2枚とも描く

位置を動かした2枚の背景画像を、実際に `screen` へ描きます。

```python
screen.blit(
    background_image,
    (0, background_y_1)
)

screen.blit(
    background_image,
    (0, background_y_2)
)
```

`blit()` に渡すものは、

```text
background_image
→ どの画像を描くか

(0, background_y_1)
→ その画像の左上をどこへ置くか
```

です。

大事なのは、`(0, background_y_1)` が**画像の左上位置**だということです。

1枚目は、

```text
x = 0
y = background_y_1
```

へ画像の左上を置きます。

2枚目も同じように、

```text
x = 0
y = background_y_2
```

へ左上を置きます。

xはどちらも0なので左右には動かず、`background_y_1` と `background_y_2` だけが変わることで上下にスクロールします。

最初は、

```python
background_y_1 = 0
background_y_2 = -480
```

なので、

```text
1枚目の左上 → (0, 0)
2枚目の左上 → (0, -480)
```

となります。

2枚目は画面の高さ480ピクセルぶん上に置かれているので、1枚目のすぐ上へつながります。

ここまでの処理は、それぞれ別です。

```text
Path
→ 画像ファイルの場所を作る
↓
image.load() + convert()
→ 画像を読み込んで扱いやすい形式にする
↓
scale()
→ 画像の大きさを640×480へ変える
↓
blit()
→ 画像をscreenの指定位置へ描く
↓
display.flip()
→ このフレームで描いた内容を実際の画面へ反映する
```

`load()` しただけでも、`scale()` しただけでも、まだ画面に画像が出るわけではありません。
