# Pg18. pygame「ゲームオーバー画面を作る」

Pg17までで、クリア画面とBACKボタンまで作りました。

でも負けると、ゲームがそのまま閉じます。

もう一度遊ぶには、ゲームを起動し直さないといけません。

> **死ぬたび再起動かよ！**

今回は、プレイヤーのHPが0になったら

> **GAME OVER**

と分かる専用画面へ切り替えます。

---

## Pg18-1. 今回使うもの

[game_over_screen.py](./game_over_screen.py) を開いてください。

今回の中心はこれです。

```text
HPが0になる
↓
game_state を game_over にする
↓
ゲームオーバー画面を表示する
```

新しい考え方を大量に増やす章ではありません。

Pg16でやったクリア画面と、

> **条件が違うだけで、ほぼ同じことをやります。**

---

## Pg18-2. 今まではHPが0になったら終了していた

Pg17までは、

```python
# player_hp が0以下なら
if player_hp <= 0:
    # running に False を入れる
    running = False
```

でした。

つまり、

```text
HP 0
↓
ゲームループ終了
↓
ウィンドウ終了
```

です。

ゲームとしてはちょっと雑です。

> **「負けたのは分かったけど、せめて負けたって言ってくれ！」**

なので、今回は終了させません。

---

## Pg18-3. game_overという状態に切り替える

こうします。

```python
# player_hp が0以下なら
if player_hp <= 0:
    # game_state に "game_over" をセットする
    game_state = "game_over"
```

これで、

```text
HP 0
↓
game_state = "game_over"
```

になります。

Pg16の、

```python
# game_state に "clear" をセットする
game_state = "clear"
```

と同じ考え方です。

違うのは、

> **何が起きたらその状態になるか**

だけです。

---

## Pg18-4. クリアとゲームオーバーを並べて見る

クリアは、

```python
# boss_active が True で boss_hp が0以下なら
if boss_active and boss_hp <= 0:
    # game_state に "clear" をセットする
    game_state = "clear"
```

ゲームオーバーは、

```python
# player_hp が0以下なら
if player_hp <= 0:
    # game_state に "game_over" をセットする
    game_state = "game_over"
```

です。

つまり、

```text
ボスHPが0 → clear
自分のHPが0 → game_over
```

です。

> **条件が違うだけで、画面を変える仕組みは同じ。**

ここが今回いちばん大事です。

---

## Pg18-5. 同時に起きたらどうする？

コードでは、

```python
# player_hp が0以下なら
if player_hp <= 0:
    # game_state に "game_over" をセットする
    game_state = "game_over"
# boss_active が True で boss_hp が0以下なら
elif boss_active and boss_hp <= 0:
    # game_state に "clear" をセットする
    game_state = "clear"
```

としています。

`elif` にしているので、

同じフレームで両方の条件が成立しても、先に判定した方だけを使います。

今回は、

> **プレイヤーHPが0ならゲームオーバー**

を先にしています。

複雑な勝敗判定ルールにはまだ入りません。

---

## Pg18-6. ゲームオーバー中はゲームを止める

ゲームオーバーになったのに、

- 敵が動く
- 弾が飛ぶ
- 背景が流れる
- ボスが撃つ

を続けたら変です。

> **「負けた後ろでまだ戦争続いてるんだけど！！！」**

なので、

```python
# game_state が "game_over" なら
if game_state == "game_over":
    ...
    # 次のループへ進む
    continue
```

とします。

`continue` で、その周回の残りを飛ばします。

これでゲームオーバー中は、

> **専用画面だけを表示する**

状態になります。

---

## Pg18-7. GAME OVERを描く

ゲームオーバー画面は、

```text
背景を塗る
↓
GAME OVER の文字画像を作る
↓
文字を置く場所を決める
↓
screenへ描く
↓
ウィンドウへ反映する
```

という順番で作っています。

> **「文字作っただけで画面に出るわけじゃないんかい！」**

ここは、1行ずつ役割を分けて見ます。

### Pg18-7-1. `screen.fill()` で画面全体を塗る

`game_over_screen.py` の191行目です。

```python
# screen に (28, 8, 12) を使った色を塗る
screen.fill((28, 8, 12))
```

`screen` は、最初に

```python
# screen に640×480のpygame画面をセットする
screen = pygame.display.set_mode((640, 480))
```

で作った、ゲームを描く画面です。

`fill` は英語で「満たす」という意味です。

ここでは、

> **screen全体を1色で塗りつぶす**

処理をしています。

```python
# (28, 8, 12) を指定する
(28, 8, 12)
```

は位置でも大きさでもなく、**色**です。

3つの数字は、

```text
28 → 赤
 8 → 緑
12 → 青
```

の順です。

この表し方を **RGB** と呼びます。

それぞれ `0` から `255` までで、

- `0` → その色の光を使わない
- `255` → その色を最大まで使う

という指定です。

今回は3つとも小さい値なのでかなり暗く、赤が少し強いため**黒に近い赤系**になります。

```python
# screen に (28, 8, 12) を使った色を塗る
screen.fill((28, 8, 12))
           └─────────┘
             1色分のRGB
```

外側の `()` は `fill()` を呼び出すための括弧です。

内側の `(28, 8, 12)` は、1色分の3つの値をまとめています。

この処理は背景画像ファイルそのものを書き換えているわけではありません。

**今のscreenを、そのフレームで一色に塗っています。**

文字を描いたあとに `fill()` すると、せっかく描いた文字まで上から塗りつぶしてしまいます。

なので、背景を先に塗ります。

また、`fill()` しただけではウィンドウの表示更新までは行いません。

### Pg18-7-2. 大きな文字用のフォントを使う

GAME OVERには、15行目で作っている `clear_font` を使っています。

```python
# clear_font に pygame.font.Font(None, 72) をセットする
clear_font = pygame.font.Font(None, 72)
```

`pygame.font.Font()` は文字を描くためのフォントを作ります。

ここでは、

```text
None → pygameの標準フォントを使う
72   → 文字の大きさ
```

です。

`clear_font` という名前はPg16のクリア画面から引き継いでいますが、Pg18ではGAME OVERの大きな文字にも同じフォントを使っています。

この時点では、まだ `GAME OVER` という文字そのものは作っていません。

### Pg18-7-3. `render()` で文字画像を作る

195行目では、GAME OVERという文字を作っています。

```python
# game_over_text に clear_font.render("GAME OVER", True, (255, 90, 90)) をセットする
game_over_text = clear_font.render(
    "GAME OVER",
    True,
    (255, 90, 90)
)
```

`render()` へ渡しているものを順番に見ると、

```text
"GAME OVER"  → 表示する文字
True         → 文字の縁を滑らかにする
(255,90,90)  → 文字の色
```

です。

文字色もRGBなので、

```text
赤 255
緑  90
青  90
```

となり、赤みの強い色になります。

そして、

```python
# game_over_text を参照する
game_over_text = ...
```

で、作った**文字の画像**を `game_over_text` に入れています。

> **renderしただけでは、まだ画面には出ません。**

文字画像を作っただけです。

### Pg18-7-4. `get_rect()` で置く場所を決める

203行目です。

```python
# game_over_text_rect に game_over_text.get_rect(center=(320, 220)) をセットする
game_over_text_rect = game_over_text.get_rect(
    center=(320, 220)
)
```

`get_rect()` は、`game_over_text` と同じ大きさの四角を作ります。

その四角の中心を、

```text
横 320
縦 220
```

へ合わせています。

ゲーム画面は `640 × 480` なので、画面の厳密な中心は、

```text
(320, 240)
```

です。

今回は縦が `220` なので、**画面中央より20ピクセル上**へ置いています。

つまり、

> 「自動で真ん中へ置く」

のではなく、

> **中心座標を `(320, 220)` と自分で指定している**

ということです。

`get_rect()` も、まだ画面へ文字を描いてはいません。

置く場所を持つ四角を作ったところです。

### Pg18-7-5. `blit()` で描いて、`flip()` で反映する

208行目で、ようやくGAME OVERの文字画像を `screen` へ描きます。

```python
# screen.blit(game_over_text, game_over_text_rect) を実行する
screen.blit(game_over_text, game_over_text_rect)
```

`blit()` へ渡しているのは、

```text
game_over_text      → 描く画像
game_over_text_rect → 描く場所
```

です。

そのあと、下の説明文も同じように描きます。

そして224行目で、

```python
# このフレームの描画内容を画面に反映する
pygame.display.flip()
```

を実行します。

`pygame.display.flip()` は、ここまで `screen` へ描いた内容を実際のウィンドウへ反映します。

つまり、この画面が見えるまでの流れは、

```text
screen.fill()
画面を塗る
    ↓
clear_font.render()
文字画像を作る
    ↓
get_rect()
文字画像を置く場所を決める
    ↓
screen.blit()
screenへ文字画像を描く
    ↓
pygame.display.flip()
ウィンドウへ反映する
```

です。

**作る・位置を決める・描く・表示を更新するは、それぞれ別の処理です。**

### Pg18-7-6. 背景色を変えてみる

背景色を変える場所は、`game_over_screen.py` の**191行目**です。

Windows / Linuxでは **Ctrl + F**、macOSでは **Command + F** を押して、

```text
screen.fill((28, 8, 12))
```

と検索しても見つけられます。

変更前は、

```python
# screen に (28, 8, 12) を使った色を塗る
screen.fill((28, 8, 12))
```

です。

たとえば黒にするなら、この1行を、

```python
# screen に (0, 0, 0) を使った色を塗る
screen.fill((0, 0, 0))
```

へ置き換えます。

ほかにも、1つずつ試せます。

白なら、

```python
# screen に (255, 255, 255) を使った色を塗る
screen.fill((255, 255, 255))
```

赤なら、

```python
# screen に (255, 0, 0) を使った色を塗る
screen.fill((255, 0, 0))
```

です。

> **3行とも追加するのではありません。191行目を、試したい色の1行へ置き換えます。**

変更したら保存します。

Windows / Linuxなら **Ctrl + S**、macOSなら **Command + S** でも保存できます。

そのあと `game_over_screen.py` をもう一度実行し、プレイヤーのHPを0にしてGAME OVER画面を表示します。

背景色が変わっていれば、RGBの変更が画面へ反映されています。
