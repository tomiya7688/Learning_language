# Pg18. pygame「ゲームオーバー画面を作る」

Pg17までで、クリア画面と戻るボタンを作りました。

でも負けたときはまだ、

> **「HP 0になった瞬間ゲーム閉じるんかい！！！」**

です。

今回は、HPが0になったらウィンドウを閉じるのではなく、

> **GAME OVER**

と分かる専用画面へ切り替えます。

---

## Pg18-1. 今回使うもの

[game_over.py](./game_over.py) を開いてください。

Pg17のゲームへ、

- ゲームオーバー状態
- HPが0になったときの状態変更
- GAME OVER画面
- ゲーム中の更新停止

を追加します。

---

## Pg18-2. 今まではHP 0でゲーム終了

Pg17までは、

```python
if player_hp <= 0:
    running = False
```

でした。

つまり、

```text
HPが0
↓
ゲームループ終了
↓
ウィンドウが閉じる
```

です。

これだと負けたことは分かっても、

> **「いや結果画面くらい出してくれ！！！」**

となります。

---

## Pg18-3. 終了ではなく状態を変える

Pg18では、

```python
if player_hp <= 0:
    game_state = "game_over"
```

にします。

これで、

```text
HPが0
↓
game_state が game_over
↓
ゲームオーバー画面を表示
```

に変わります。

> **ゲームを終わらせるんじゃなくて、画面を変える。**

この考え方はPg16のクリア画面と同じです。

---

## Pg18-4. Pg16と何が違う？

Pg16では、

```python
if boss_active and boss_hp <= 0:
    game_state = "clear"
```

でした。

Pg18では、

```python
if player_hp <= 0:
    game_state = "game_over"
```

です。

並べると、

```text
ボスHPが0
↓
clear

プレイヤーHPが0
↓
game_over
```

です。

> **条件が違うだけで、やってることほぼ同じやん！！！**

そこが今回のポイントです。

---

## Pg18-5. GAME OVER画面を描く

`game_state == "game_over"` のときは、

```python
screen.fill((24, 6, 10))
```

で背景を塗ります。

その上に、

```python
game_over_text = game_over_font.render(
    "GAME OVER",
    True,
    (255, 90, 90)
)
```

で文字を作ります。

中央へ置けば、

```python
game_over_text_rect = game_over_text.get_rect(
    center=(320, 220)
)
screen.blit(
    game_over_text,
    game_over_text_rect
)
```

で専用画面になります。

---

## Pg18-6. ゲームオーバー中は戦わせない

GAME OVER画面を出しているのに、

- 敵が動く
- 弾が飛ぶ
- ボスが撃つ
- プレイヤーが動く

では変です。

> **「もう負けてんのに後ろで戦闘続いてるんだけど！！！」**

なのでゲームオーバー画面を描いたあと、

```python
pygame.display.flip()
clock.tick(60)
continue
```

とします。

`continue` で、その周回の残りを飛ばします。

これでゲーム中の更新処理へ進みません。

---

## Pg18-7. SPACEも撃てない

SPACEで弾を撃つ処理は、

```python
if (
    event.key == pygame.K_SPACE
    and game_state == "playing"
):
```

となっています。

つまり、

```text
playing のときだけ撃てる
```

です。

`game_over` のときにSPACEを押しても弾は増えません。

> **画面を変えたら、操作もその画面に合わせて止める。**

ということです。

---

## Pg18-8. 状態が3つ以上になってきた

今は、

```text
playing
clear
game_over
menu
```

という状態があります。

でも、まだ難しい設計へは進みません。

今やっているのは、

> **「今どの画面か」を文字で覚えて、必要な画面だけ描く**

だけです。

タイトル画面などが増えてきたら、あとで整理すればOKです。

---

## Pg18-9. クリア画面とゲームオーバー画面は兄弟

今回の2つは、

```text
勝った
↓
clear

負けた
↓
game_over
```

という違いしかありません。

どちらも、

```text
条件が成立
↓
game_state を変える
↓
専用画面を描く
↓
ゲーム中の更新を止める
```

です。

> **新しい画面だから全部別物、ではありません。**

同じ仕組みを別の条件で使っています。

---

## Pg18-10. 次は「もう一回やりたい」

ゲームオーバー画面は出ました。

でも今は、

> **「負けた。はい終了。もう一回やらせてくれ！！！」**

状態です。

次は、ゲームオーバー画面に再開ボタンを付けます。

ただし、画面を `playing` に戻すだけでは足りません。

- HP
- 敵
- 弾
- ボス

も最初の状態へ戻す必要があります。

そこをPg19でやります。
