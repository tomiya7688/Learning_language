# Pg10. pygame「ボスの強さを調整する」

Pg9では、ボスの弾をわざと巨大化して無理ゲーにしました。

原因はもう分かっています。

> **「原因わかってるなら、まずそこ直せ！」**

今回は、巨大すぎるボス弾を見て避けられるサイズへ戻します。

いきなり全部の数値を触りません。

まず一番悪いところだけ直して、実際に遊びます。

---

## Pg10-1. 今回作るもの

[balanced_boss.py](./balanced_boss.py) を開いてください。

`balanced` は「バランスが取れた」という意味です。

Pg9との大きな違いは、ボス弾の大きさです。

---

## Pg10-2. Pg9はこうだった

Pg9では、

```python
boss_bullet_width = 700
boss_bullet_height = 260
```

でした。

640×480の画面に対して、これは明らかに大きすぎます。

---

## Pg10-3. まず弾サイズだけ直す

Pg10では、

```python
boss_bullet_width = 48
boss_bullet_height = 48
```

にします。

これで、

- 見える
- 避ける場所がある
- 当たり判定も分かりやすい

状態になります。

---

## Pg10-4. 他の数字はすぐ触らない

Pg9では巨大弾を確実に体験するため、発射間隔を60フレームにしていました。

Pg10では弾サイズを普通へ戻したうえで、

```python
boss_bullet_speed = 4
boss_fire_interval = 120
```

と、落ち着いて避けられる間隔へ戻します。

> **「難しいから全部変えよ！」**

とやると、何が効いたのか分からなくなります。

まず問題だった弾サイズだけ直します。

---

## Pg10-5. 調整は1個ずつ

ゲームバランス調整では、

```text
問題を見つける
↓
原因を1つ決める
↓
その数字だけ変える
↓
遊ぶ
↓
まだダメなら次を変える
```

くらいで十分です。

全部同時に変えると、どの変更が効いたのか分かりません。

今回の主修正は弾サイズです。発射間隔はPg9で「巨大弾を確実に見せる」ために短くしていた分を、通常値へ戻します。

---

## Pg10-6. 見た目と当たり判定も同じサイズ

```python
boss_bullet_rect = pygame.Rect(
    boss_bullet[0] - boss_bullet_width // 2,
    boss_bullet[1],
    boss_bullet_width,
    boss_bullet_height
)
```

なので、変数を小さくすると当たり判定も一緒に小さくなります。

描画側も同じ変数を使っているので、

> **見た目だけ小さいのに当たり判定は巨大**

という事故も起きません。

---

## Pg10-7. 正解の数字は1つではない

今回は、

```python
boss_bullet_width = 48
boss_bullet_height = 48
```

にしています。

でも、

```python
40
```

でも、

```python
60
```

でも、ゲームとして成立するかもしれません。

大事なのは、

> **その数字が唯一の正解だから使う**

のではなく、

> **実際に遊んで、避けられるか確認する**

ことです。

---

## Pg10-8. まだ難しいなら次を触る

弾サイズを直してもまだ難しいなら、

```python
boss_bullet_speed
```

や、

```python
boss_fire_interval
```

を調整します。

たとえば、

```python
boss_bullet_speed = 3
```

にすれば少し遅くなります。

```python
boss_fire_interval = 150
```

にすれば発射間隔が長くなります。

---

## Pg10-9. でも簡単すぎてもダメ

逆に、

```python
boss_bullet_speed = 1
boss_fire_interval = 600
```

のようにすると、ほとんど攻撃してこないボスになります。

> **「避けられるようにしろとは言ったけど、寝てても勝てるようにしろとは言ってない！」**

難しすぎず、簡単すぎず。

その間を探すのがゲームバランス調整です。

---

## Pg10-10. Pg9とPg10を比べる

### Pg9

```python
boss_bullet_width = 700
boss_bullet_height = 260
```

### Pg10

```python
boss_bullet_width = 48
boss_bullet_height = 48
```

ゲームロジック自体は大きく変えていません。

それでも遊びやすさは大きく変わります。

---

## Pg10-11. CIも通常基準へ戻る

Pg9では、

> **巨大弾であること**

自体をCIで確認していました。

Pg10では逆に、通常のバランス基準へ戻します。

つまり、

> **Pg9はわざと失敗**
>
> **Pg10でちゃんと直す**

ところまでCIでも確認します。

---

## Pg10-12. 実装して終わりではない

ゲームでは、

```text
機能を作る
↓
遊ぶ
↓
問題を見つける
↓
調整する
↓
また遊ぶ
```

を繰り返します。

> **調整もゲーム開発です。**

コードが動いた時点で終わりではありません。

---

## Pg10-13. ここまでで覚えること

1. バランス調整では原因を1つずつ直す
2. 弾サイズもゲーム性を大きく変える
3. 見た目と当たり判定は同じ変数を使うとズレにくい
4. 正解の数値は1つではない
5. 実際に遊んで調整する
6. 難しすぎても簡単すぎてもよくない
7. Pg9の失敗をPg10で直すところまでが教材
