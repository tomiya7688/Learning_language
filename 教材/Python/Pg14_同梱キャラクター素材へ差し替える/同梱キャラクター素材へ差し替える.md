## Pg14-2. 透明PNGを読み込む

キャラクター画像は、もともと透明部分を持つPNGです。

自機画像は、

```python
player_image = pygame.image.load(
    str(assets_path / "player_ship.png")
).convert_alpha()
```

で読み込みます。

`player_image` の `player` は「プレイヤー」、`image` は「画像」です。

つまり `player_image` には、**読み込んだ自機画像そのもの**が入ります。

`pygame.image.load(...)` でPNGを読み込み、そのあと、

```python
.convert_alpha()
```

を呼んでいます。

`convert_alpha()` は、PNGが**もともと持っている透明度を保ったまま**、画面へ描きやすい内部形式の画像を作ります。

ここで透明部分を新しく自動判定しているわけではありません。

たとえば背景が白い普通の画像を読み込んだだけで、白い部分が勝手に透明になる機能ではありません。

Pg13の背景画像では透明度が不要だったので `convert()`、今回は透明PNGなので `convert_alpha()` を使っています。

## Pg14-5. 画像の中心を座標へ合わせる

画像を読み込んだだけでは、画面のどこへ置くかはまだ決まっていません。

プレイヤーは、

```python
player_image_rect = player_image.get_rect(
    center=(player_x, player_y)
)
```

として、画像を置くためのRectを作ります。

`player_image` と `player_image_rect` は別のものです。

```text
player_image
→ 自機の画像

player_image_rect
→ その画像と同じ幅・高さと、置き場所を持つ四角形
```

`get_rect()` は、`player_image` と同じ幅・高さのRectを作ります。

そこへ、

```python
center=(player_x, player_y)
```

と指定しています。

これは、**Rectの中心**をプレイヤーの横位置・縦位置へ合わせる指定です。

```text
player_x
→ 中心のx

player_y
→ 中心のy
```

です。

Rectの中心を指定しているので、これは画像の左上を `(player_x, player_y)` に置く指定ではありません。

`get_rect()` を呼んだだけでは、画像が画面へ表示されるわけでも、画像自体が勝手に移動するわけでもありません。

ここでは、**画像と同じ大きさの四角に置き場所を決めただけ**です。

### 初期位置を変えて確認してみる

`character_sprites.py` の **55行目** を変更します。

VS Codeで **Ctrl + F**、macOSでは **Command + F** を押して、

```text
player_x = 320
```

を検索してください。

変更前:

```python
player_x = 320
```

変更後:

```python
player_x = 200
```

保存して再実行すると、自機画像の中心位置が左へ移動します。

`player_image_rect` も当たり判定用 `player_rect` も同じ `player_x` を使っているため、見た目だけではなく当たり判定の位置も一緒に移動します。

確認したら `player_x = 320` に戻してください。

## Pg14-6. blit()で描く

位置が決まったので、ここで初めて画像を画面へ描きます。

```python
screen.blit(
    player_image,
    player_image_rect
)
```

`blit()` に渡している2つは、

```text
player_image
→ どの画像を描くか

player_image_rect
→ その画像をどこへ置くか
```

です。

`player_image_rect` には画像と同じ幅・高さだけでなく、`center=(player_x, player_y)` で決めた画面上の位置も入っています。

そのため、

```python
screen.blit(player_image, player_image_rect)
```

で、自機画像をそのRectの位置へ実際に描けます。

つまり自機は、

```text
player_image
→ 画像を用意する
↓
player_image.get_rect(center=...)
→ 画像と同じ大きさのRectを作り、置き場所を決める
↓
screen.blit(player_image, player_image_rect)
→ 画像をその場所へ描く
```

という流れです。

通常敵も同じです。

```python
enemy_image_rect = enemy_image.get_rect(
    center=(enemy.x, enemy.y)
)

screen.blit(
    enemy_image,
    enemy_image_rect
)
```

ボスも、

```python
boss_image_rect = boss_image.get_rect(
    center=(boss_x, boss_y)
)

screen.blit(
    boss_image,
    boss_image_rect
)
```

という同じ流れで描いています。

`get_rect()` は位置を持つ四角を作る処理、`blit()` は画像を実際に `screen` へ描く処理です。

## Pg14-7. 当たり判定も画像サイズと揃える

当たり判定にも、画像と同じ大きさのRectを使います。

```python
player_rect = player_image.get_rect(
    center=(player_x, player_y)
)
```

`player_rect` は、`player_image` と同じ幅・高さを持つRectです。

今回の自機画像は40×40なので、当たり判定の四角も40×40になります。

敵画像は40×30、ボス画像は120×60なので、今まで使っていた四角形の大きさとも揃っています。

ここでも `get_rect()` は、画像を画面へ描く処理ではありません。

```text
player_rect
→ 当たり判定などで使う位置・大きさの四角

player_image_rect
→ 自機画像を描く場所として使う位置・大きさの四角
```

のように、用途は違いますが、どちらも同じ `player_image` から同じ中心座標で作っています。

そのため、見た目と当たり判定の位置・大きさを揃えやすくなります。

### 透明部分もRectの中に入る

Rectは、画像の**見えている輪郭だけ**を自動で判定するものではありません。

PNGの透明部分があっても、`get_rect()` で作るRectは画像全体を囲う四角形です。

つまり今回の当たり判定は、

> **透明部分も含んだ画像全体の四角形**

で行います。

キャラクターの見える部分だけに沿った判定へ自動で変わるわけではありません。

この章では、画像の輪郭に合わせる別の判定方法は追加せず、これまでと同じ四角形の当たり判定を使います。
