# Issueの優先度運用

Issueには、作業を進める順序を表す `P0`〜`P8` のラベルを**1つ**付けます。
新規Issueを作るときに選び、教材の需要・依存関係・実装準備が変わったら見直します。

## 優先度の意味

| ラベル | 対象 | 例 |
| --- | --- | --- |
| P0 | 緊急対応 | mainの破損、教材全体に影響する大量のリンク切れ、公開物のライセンス事故 |
| P1 | Python教材の土台になる優先作業 | 入口・構成・学習順の整理、初学者が進めなくなる説明不足、基盤となる共通修正 |
| P2 | Python教材の通常作業 | 章の追加、説明や既存サンプルの改善 |
| P3 | Python教材の将来・発展作業 | 応用編、上級編、基礎を整えたあとで追加する教材 |
| P4 | Pythonの次に着手する他言語 | DNCL、Scratch |
| P5 | P4のあとに進める他言語 | Rust、なでしこ、Zig、Gleam、Fortran |
| P6 | そのあとに進める他言語 | Tomiyaの言語、C、Go、C++、Common Lisp、Haskell |
| P7 | さらにあとに進める他言語 | Java、C#、Lua、SQL |
| P8 | 教材化をさらに後回しにする他言語 | Simula、Smalltalk、ActionScript、Bend、Squirrel |

### P0は緊急対応専用

通常の教材追加・改善にはP0を使いません。P0のopen Issueがない状態で構いません。
言語を問わず、リポジトリ全体へ即時影響する事故が起きたときに使います。

### Pythonと共通作業

Python教材はP1〜P3で管理します。
Pythonにも適用する教材共通の方針・保守作業は、影響の大きさと実装順に応じてP1〜P3へ置きます。
Python以外の言語だけを対象とする通常作業はP4以降へ置きます。

表の言語例は当面の割り当てです。需要や実装準備が変われば、Issue単位で上げ下げします。

## 次の作業の選び方

1. 最新のopen Issueと関連PRを確認します。
2. P0から順に確認し、着手できる作業を選びます。
3. 未完了の前提作業がある場合は、その依存関係を確認して前提から進めます。
4. 親Issueを分割した子Issueには親へのリンクを残します。子のラベルが低くても、上位の親を完了するために必要な作業であれば、その関係を確認して進めます。
5. 同じ優先度では、入口・構成・実行手順など、ほかの教材作業の土台になるものを先に進めます。

扱いたい言語や作業の種類だけを理由に、着手できる上位のIssueを飛ばしません。
前提待ちで進められない場合は、その理由を残し、次に着手できるIssueへ進みます。

## Issueを作成・整理するとき

- 新規Issueには優先度ラベルを1つ付けます。
- 内容を1回の変更で完了できる単位に分け、前提Issueや親Issueがあればリンクします。
- 作業順を変えるときは、既存の優先度ラベルを外して新しい優先度を付けます。分類などのほかのラベルは残します。
- 完了条件を満たしたIssueは、関連PRのマージと成果物を確認してクローズします。
- まだ完了していない親Issueは、子Issueの一部を終えただけではクローズしません。

## 言語の教材化優先順位との関係

[将来対応予定](./将来対応予定.md#対応優先順位)の「言語優先度1〜5」は、どの言語を先に教材化するかを表します。
IssueのP0〜P8は、Pythonや共通保守も含め、リポジトリ全体の中でいつ着手するかを表します。

当面、他言語は言語優先度1をP4、2をP5、3〜4をP6〜P7、5をP8の目安にします。
言語候補一覧の並び順を、そのままIssueの作業順には使いません。
