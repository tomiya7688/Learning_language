# 将来対応予定

このファイルは、まだ1つのIssueへ分解する段階ではない大きな構想や、将来対応したい方向性をまとめるための場所です。

Issueは原則として **1実装単位** で管理します。

そのため、

- 1つのIssueでは大きすぎるもの
- まだ実装順や分割方法が決まっていないもの
- 複数のIssueへ分割する前提の長期構想
- 将来追加したい言語・教材系列
- プロジェクト全体に関わる大きな方針

は、まずこのファイルへ置きます。

実装できる大きさまで内容が固まったら、このファイルから個別Issueへ切り出します。

## 言語に対する先入観を持ち込まない

このプロジェクトでは、

> 「この言語は○○専用」

という世間の先入観を、そのまま教材へ持ち込まないようにします。

たとえば、MicroPythonはRaspberry Pi専用の言語ではありません。

Raspberry Pi Picoなどで使われることはありますが、MicroPython自体はマイコンなどの小さな環境でPythonを使うための実装です。

同様に、

- Arduino = 教育用ボードだけのお遊び
- COBOL = 古いだけの言語
- Lisp = 研究者だけの言語
- Assembly = 全部を手書きするための言語

といった固定観念だけで教材の用途を決めません。

教材では、

- 何ができるのか
- どんな環境で使えるのか
- どんな場面で役に立つのか

を実際の用途から説明します。

## このファイルからIssueへ移す基準

次の状態になったら、個別Issueへ分割します。

1. 実装内容が具体的になった
2. 1PRで終わる単位へ分けられる
3. 実装順が決まった
4. 完了条件を書ける

それまでは、このファイルで長期構想として管理します。

## オフィスソフト向けBasic系

VBAだけでなく、LibreOffice Basicも将来対応候補に含めます。

どちらも、

> オフィスソフトの中だけで使う特殊な専用言語

のように見えやすく、一般的なプログラミング言語教材から入口を見つけにくい分野です。

将来教材化する場合は、

- どこでコードを書くのか
- どう実行するのか
- セルやシート、文書をどう操作するのか
- 普通のBasic系言語として見たときに何が共通しているのか
- VBAとLibreOffice Basicで何が違うのか

を、最初から実際の画面操作込みで説明する方向にします。

「専用言語っぽく見えるから分からない」を減らす教材にします。

## Markdown

Markdownも将来対応候補に含めます。

このリポジトリ自体が教材をMarkdownで書いているため、
当たり前のように `.md` を読ませるだけでなく、
Markdownそのものを学べる教材も用意します。

扱う候補:

- Markdownとは何か
- `.md` ファイルとは何か
- 見出し
- 箇条書き
- 番号付きリスト
- リンク
- 画像
- コードブロック
- 引用
- 表
- GitHubでMarkdownがどう表示されるか
- README.mdを書く
- 教材やメモ、仕様書を書く用途

このプロジェクトではMarkdownを頻繁に使うため、
「教材を読むための前提知識」にするのではなく、
必要ならMarkdown自体も学べるようにします。
